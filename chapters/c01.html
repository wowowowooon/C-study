2프로그램이 실행되기까지: 빌드 4단계

CPU는 C++ 문장을 읽지 못합니다. CPU가 실행할 수 있는 것은 0과 1로 된 기계어(machine code)뿐입니다. 그래서 사람이 쓴 소스 코드(source code)를 기계어로 된 실행 파일(executable)로 바꾸는 과정이 필요하고, 이 과정 전체를 빌드(build)라고 부릅니다.

먼저 이 챕터 내내 쓸 7줄짜리 프로그램을 보겠습니다. 파일 이름은 hello.cpp라고 하겠습니다. .cpp는 C++ 소스 파일의 확장자입니다.

#include <iostream>
using namespace std;

int main() {
    cout << "Hello, World!" << '\n';
    return 0;
}
실행 결과
Hello, World!

각 줄의 뜻은 3절에서 하나씩 뜯어봅니다. 지금은 이 텍스트 파일이 어떤 단계를 거쳐 화면에 Hello, World!를 찍는 프로그램이 되는지만 보겠습니다.

  1. 전처리(preprocessing): #으로 시작하는 줄(전처리 지시문)을 처리합니다. 위 hello.cpp에서는 첫 줄 #include <iostream>이 여기에 해당합니다. 이 줄은 iostream이라는 파일의 내용을 그 자리에 통째로 붙여 넣으라는 명령입니다. 주석(//로 시작하는 설명 글, 7절)도 이때 지워집니다. 결과는 여전히 C++ 텍스트입니다.
    전처리 명령에는 #define도 있습니다. 위 코드에는 없지만, #define A B라고 쓰면 코드 속 A를 B로 글자 그대로 바꾸라는 뜻입니다. 직접 해 보는 예제는 이 절 아래 #define: 글자 그대로 바꾸기에 있습니다.
  2. 컴파일(compile): 전처리가 끝난 코드의 문법을 검사하고 CPU의 기계어로 번역해 오브젝트 파일(object file) hello.o를 만듭니다. 세미콜론 누락 같은 문법 에러는 이 단계에서 나옵니다(9절). 정확히는 기계어 직전의 어셈블리 코드로 바꾸는 단계와 그것을 기계어로 바꾸는 어셈블 단계로 나뉘지만, 지금은 한 단계로 봐도 충분합니다.
  3. 링크(link): 오브젝트 파일을 라이브러리(library)와 연결해 실행 파일 하나로 완성합니다. 라이브러리는 미리 만들어 둔 기계어 묶음입니다. 예를 들어 cout이 글자를 실제로 내보내는 코드는 내 파일이 아니라 C++ 표준 라이브러리 안에 있습니다. main이 없거나 철자가 틀리면 이 단계에서 에러가 납니다.
  4. 실행(run): 운영체제가 실행 파일을 메모리에 올리고 main부터 실행합니다.

g++ 명령에 옵션을 주면 단계를 하나씩 끊어서 볼 수 있습니다. 아래는 64비트 리눅스의 g++ 13으로 실제로 실행한 기록입니다. $ 뒤가 입력한 명령이고, 그 아래 줄이 결과입니다. # 뒤는 설명입니다.

#include <iostream>

}

g++ -E로 전처리 결과를 만들어 맨 끝을 보면, 3만 줄이 넘는 iostream 내용 뒤에 내 코드가 이렇게 바뀌어 있습니다.

using namespace std;

int main() {
    cout << "Hi, STM32!" << '\n';
    return 0;
}

GREETING이 사라지고 그 자리에 "Hi, STM32!"가 들어갔습니다. 전처리기는 C++ 문법을 모르고 글자만 바꿉니다. 그래서 #define은 편리하지만 실수를 숨기기도 쉽습니다. C++에서 상수를 만들 때는 const를 더 권장하고(2장), 매크로의 함정은 29장에서 자세히 다룹니다.

오브젝트 파일이 '나중에 연결할 이름'을 비워 둔다는 것은 nm 명령으로 직접 볼 수 있습니다. 아래는 nm -C hello.o 결과 중 두 줄입니다.

                 U std::cout
0000000000000000 T main

T는 '이 파일 안에 코드가 있다'(main), U는 undefined, 즉 '쓰기는 하는데 여기엔 없다'(cout)는 표시입니다. 링커가 하는 일이 바로 이런 U를 라이브러리에서 찾아 연결하는 것입니다. 정확히는 리눅스의 기본 방식이 '동적 링크'라서 라이브러리의 실제 코드는 실행할 때 운영체제가 함께 불러오지만, 지금은 '링크 단계에서 라이브러리와 연결된다'고 이해하면 충분합니다.

STM32CubeIDE의 Build도 똑같은 과정입니다. 다른 점은 컴파일러가 PC용 g++가 아니라 ARM용 arm-none-eabi-gcc라는 것뿐입니다(none은 운영체제가 없는 환경이라는 뜻). 이렇게 지금 쓰는 PC와 다른 CPU를 위한 기계어를 만드는 컴파일러를 크로스 컴파일러(cross compiler)라고 합니다.

  • main.c, stm32f4xx_hal_gpio.c 같은 .c 파일과 스타트업 어셈블리 파일 startup_stm32….s가 각각 .o로 컴파일됩니다. Debug 폴더에 쌓이는 .o 파일들이 바로 이것입니다.
  • 링커가 링커 스크립트(.ld: Flash와 RAM의 주소와 크기)에 맞춰 모든 .o를 합쳐 .elf를 만듭니다. 운영체제가 없으니 필요한 라이브러리 코드도 전부 이 안에 들어갑니다.
  • arm-none-eabi-objcopy가 .elf에서 보드에 구울 .hex/.bin을 뽑아내고, ST-LINK로 Flash에 씁니다(CubeIDE의 디버거는 .elf를 바로 쓰기도 합니다).

위 file 명령 결과처럼 리눅스의 g++가 만든 hello.o와 hello도 .elf와 같은 ELF 형식입니다. ELF는 리눅스와 많은 임베디드 툴체인이 함께 쓰는 실행 파일·오브젝트 파일 형식의 이름입니다. ESP-IDF, 젯슨에서 쓰는 CMake, ROS 2의 colcon 같은 빌드 도구도 결국 이 단계들을 자동으로 돌려 주는 도구입니다.

1줄: #include <iostream>

iostream은 input/output stream(입출력 흐름)의 줄임말입니다. 이런 파일을 헤더 파일(header file)이라고 하며, 어떤 기능을 쓸 수 있는지 알려 주는 선언이 들어 있습니다. 이 환경에서는 /usr/include/c++/13/iostream이 실제 파일입니다. 이름을 < >로 감싸면 '컴파일러에 딸린 표준 위치에서 찾으라'는 뜻이고, 내가 만든 헤더는 #include "my.h"처럼 큰따옴표로 씁니다(30장). cout을 쓰려면 이 줄이 반드시 있어야 하며, 빼먹으면 어떻게 되는지는 9절에서 봅니다.

#include 줄 끝에는 세미콜론을 붙이지 않습니다. #으로 시작하는 줄은 C++ 문장이 아니라 전처리기에게 주는 명령이기 때문입니다. 붙이면 g++는 에러가 아니라 경고만 내므로 그냥 넘어가기 쉽습니다.

#include <iostream>;
using namespace std;

int main() {
    cout << "Hello" << '\n';
    return 0;
}
컴파일 경고
main.cpp:1:20: warning: extra tokens at end of #include directive
    1 | #include <iostream>;
      |                    ^

extra tokens는 '쓸데없는 글자가 더 붙었다'는 뜻입니다. 경고도 에러처럼 고치는 습관을 들이세요.

2줄: using namespace std;

C++ 표준 라이브러리의 이름(cout, cin, string, endl …)은 모두 std(standard)라는 이름 공간(namespace) 안에 들어 있습니다. 이름 공간은 사람의 성(姓)과 비슷합니다. 정식 이름은 std::cout, 즉 'std 집안의 cout'이고 ::는 '~ 안의'라는 뜻입니다. using namespace std;는 '이 파일에서는 std 집안의 이름을 성 없이 부르겠다'는 선언입니다. 이 줄이 없으면 이렇게 써야 합니다.

#include <iostream>

int main() {
    std::cout << "Hello, World!" << '\n';
    return 0;
}
실행 결과
Hello, World!

using 줄도 없고 std::도 붙이지 않으면 컴파일러는 cout이 누구인지 모릅니다.

#include <iostream>

int main() {
    cout << "Hello" << '\n';
    return 0;
}
컴파일 에러

    4 |     cout << "Hello" << '\n';
      |     ^~~~

그럼 항상 using namespace std;를 쓰면 될까요? 장단점이 있습니다.

구분내용
장점코드가 짧아집니다. 코딩테스트처럼 혼자 쓰는 짧은 한 파일짜리 코드에서는 편리합니다.
단점std 안에는 count, max, min, swap, sort 같은 흔한 이름이 아주 많습니다. 내가 같은 이름을 만들면 어느 쪽을 말하는지 정할 수 없어 에러가 납니다.

아래 코드의 int count = 0;은 2장에서 배울 '변수 만들기'입니다. 지금은 'count라는 이름을 하나 만들었다'고만 보세요. <algorithm> 헤더(11장)에 들어 있는 std::count와 이름이 겹칩니다.

#include <iostream>
#include <algorithm>
using namespace std;

int count = 0;

int main() {
    cout << count << '\n';
    return 0;
}
컴파일 에러 (앞부분)
main.cpp: In function 'int main()':
main.cpp:8:13: error: reference to 'count' is ambiguous
    8 |     cout << count << '\n';
      |             ^~~~~

ambiguous는 '모호하다'는 뜻입니다. 내가 만든 count인지 std::count인지 정할 수 없다는 것입니다. 그래서 이 노트는 다음 규칙을 따릅니다.

핵심 정리
  • 코딩테스트 코드에서는 편의상 using namespace std;를 씁니다. 이 노트의 C++ 예제도 모두 씁니다.
  • 여러 사람이 함께 만드는 큰 프로젝트, 특히 헤더 파일(.h)에서는 쓰지 않고 std::를 붙입니다. 헤더는 #include로 여러 파일에 그대로 붙여 넣어지므로, 헤더 속 using이 그 헤더를 쓰는 모든 파일로 퍼지기 때문입니다. ROS 2 같은 현업 C++ 코드에 std::가 잔뜩 보이는 이유입니다.

4·7줄: int main() { … }

main은 함수(function)입니다. 함수는 '이름이 붙은 명령 묶음'이며 8장에서 직접 만들어 봅니다. 지금 알아야 할 것은 세 가지입니다.

  • 프로그램은 언제나 main의 첫 문장부터 실행됩니다. 그래서 main은 프로그램에 정확히 하나 있어야 하고, 철자도 정확히 main이어야 합니다.
  • {와 } 사이가 main에 속한 문장들입니다. 이렇게 중괄호로 묶인 범위를 블록(block)이라고 합니다. 여는 괄호와 닫는 괄호는 반드시 짝이 맞아야 합니다.
  • 앞의 int는 'main이 끝날 때 정수(integer) 하나를 돌려준다'는 뜻이고, 그 정수가 6줄의 0입니다. 뒤의 ()는 '받는 값이 없다'는 뜻입니다. 초기 코드에 int main(void)라고 적혀 있다면 C++에서는 int main()과 같은 뜻입니다.

옛날 책이나 일부 예제에서 void main()을 볼 수 있지만, 표준 C++에서 main은 반드시 int를 돌려줘야 합니다. g++는 error: '::main' must return 'int' 에러를 냅니다.

6줄: return 0;

return은 '함수를 끝내고 값을 돌려준다'는 뜻입니다. main이 돌려준 값은 운영체제가 받는데, 관례상 0은 '정상 종료', 0이 아닌 값은 '무언가 잘못됐다'는 신호입니다. 리눅스 터미널에서는 방금 끝난 프로그램이 돌려준 값을 echo $?로 볼 수 있습니다.

$ ./hello
Hello, World!
$ echo $?
0
PS> .\hello
Hello, World!
PS> $LASTEXITCODE
0

방금 끝난 프로그램의 return 값(종료 코드)은 리눅스에서는 echo $?, PowerShell에서는 $LASTEXITCODE로 봅니다.

return 3;으로 바꾸면 echo $?(PowerShell은 $LASTEXITCODE)는 3을 보여 줍니다. 채점 시스템에 따라 0이 아닌 값을 '비정상 종료(런타임 에러)'로 처리하기도 하니, 입출력형 문제의 main은 항상 return 0;으로 끝내세요. 참고로 main에 한해서는 return 0;을 생략해도 0을 돌려준 것으로 친다는 규칙이 표준에 있지만, 이 노트는 의도를 분명히 하려고 항상 씁니다.

세미콜론: 문장의 끝

C++에서 문장(statement)을 끝내는 것은 줄바꿈이 아니라 세미콜론 ;입니다. 한국어 문장의 마침표와 같습니다. 컴파일러는 ;를 만날 때까지를 한 문장으로 읽으므로, 한 문장을 여러 줄에 나눠 써도 되고 한 줄에 두 문장을 써도 됩니다(8절). ;가 붙지 않는 줄도 있습니다.

대소문자 구분

C++는 대문자와 소문자를 다른 글자로 봅니다. cout, Cout, COUT은 서로 다른 이름이고, 이 중 표준 라이브러리에 있는 것은 cout뿐입니다. int, return, using 같은 C++ 예약어(keyword)도 전부 소문자입니다. 대소문자를 틀리면 어떤 에러가 나는지는 8절에서 봅니다.

PC 프로그램은 return 0;으로 끝나서 운영체제에게 돌아갑니다. 그런데 STM32 펌웨어에는 돌아갈 운영체제가 없습니다. 전원이 들어오면 스타트업 코드(startup_stm32….s의 리셋 핸들러)가 RAM을 초기화한 뒤 main을 부르고, main은 끝나지 않는 반복문 while (1) 안에서 전원이 꺼질 때까지 일합니다. CubeMX가 만들어 주는 main.c의 뼈대가 이 모양입니다(반복문은 5장에서 배웁니다).

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    while (1)
    {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
        HAL_Delay(500);
    }
}

같은 main이라도 PC에서는 '할 일을 하고 끝나는 함수', MCU에서는 '영원히 도는 함수'입니다.

using namespace std; 줄을 지운 뒤에도 컴파일되게 하려면 cout << "Hi" << '\n';을 어떻게 고쳐야 할까요?

cout은 character output의 줄임말이고 '씨아웃'이라고 읽습니다. 프로그램의 표준 출력(standard output)으로 글자를 내보내는 통로입니다. 터미널에서 실행하면 표준 출력은 화면이고, 채점기에서 실행하면 채점기가 이 출력을 받아 정답과 비교합니다. <<는 '오른쪽 값을 왼쪽 cout으로 보낸다'는 뜻이며, 화살표 방향이 데이터가 흐르는 방향입니다.

문자열 리터럴과 이어 쓰기

큰따옴표로 감싼 "Hello"를 문자열 리터럴(string literal)이라고 합니다. 리터럴(literal)은 '값을 코드에 글자 그대로 적은 것'이라는 뜻입니다. 따옴표 안은 데이터라서 공백까지 그대로 출력되고, 따옴표 밖은 코드로 해석됩니다. <<를 여러 번 이어 쓰면 한 문장에서 여러 값을 출력할 수 있습니다.

#include <iostream>
using namespace std;

int main() {
    cout << "STM32" << " + " << "ESP32" << '\n';
    cout << "STM32 + ESP32" << '\n';
    cout << "Jetson";
    cout << " Nano" << '\n';
    return 0;
}

STM32 + ESP32
Jetson Nano

첫 줄과 둘째 줄의 결과가 같습니다. <<로 이어 쓴 값들은 왼쪽부터 순서대로, 사이에 아무것도 끼우지 않고 출력됩니다. 셋째·넷째 문장처럼 문장을 나눠도 마찬가지로 이어서 출력됩니다. " Nano" 앞의 공백이 없었다면 JetsonNano가 됐을 것입니다. 끝의 '\n'은 줄을 바꾸는 글자이며 5절에서 자세히 봅니다.

이어 쓰기가 되는 이유: cout << "STM32"를 실행하면 그 결과로 다시 cout이 남습니다. 그래서 cout << "STM32" << " + "는 (cout << "STM32") << " + ", 즉 cout << " + "로 이어집니다.

endl과 버퍼

출력한 글자는 화면으로 바로 가지 않습니다. 먼저 버퍼(buffer)라는 메모리 공간에 모였다가 한꺼번에 운영체제로 넘어갑니다. 터미널 화면에 출력할 때는 보통 줄바꿈마다 내보내지만, 채점기처럼 출력을 파일이나 파이프로 받을 때는 버퍼가 찰 때까지 모읍니다. 운영체제에 '이것 좀 써 줘'라고 요청하는 일(시스템 콜)은 비용이 크기 때문에, 조금씩 자주 보내지 않고 모아서 보내는 것입니다. endl은 줄마다 '지금 바로 보내'라고 강제하므로 출력할 줄이 많으면 느려집니다.

8공백, 들여쓰기, 대소문자

컴파일러는 단어와 기호 사이의 공백·탭·줄바꿈을 대부분 무시합니다. 그래서 아래 두 프로그램은 똑같이 동작합니다.

한 줄에 몰아 쓴 코드

#include <iostream>
using namespace std;
int main(){cout<<"Hi"<<'\n';return 0;}
실행 결과
Hi

들여쓴 코드

#include <iostream>
using namespace std;

int main() {
    cout << "Hi" << '\n';
    return 0;
}
실행 결과
Hi

컴퓨터에게는 같지만 사람에게는 오른쪽이 훨씬 읽기 쉽습니다. 블록 { } 안쪽은 한 단계 들여 써서(이 노트는 공백 4칸) '이 문장들은 main 안에 있다'는 구조가 눈에 보이게 합니다. 4장 이후 블록 안에 블록이 겹겹이 들어가기 시작하면, 들여쓰기가 엉망인 코드는 사람이 읽을 수 없게 됩니다.

반대로 공백이 의미를 갖는 곳도 있습니다.

  • 따옴표 안: "a b"의 공백 두 칸은 그대로 출력됩니다.
  • 한 단어나 한 기호의 중간: co ut, re turn, < <처럼 쪼개면 다른 것이 됩니다. co ut은 error: 'co' was not declared in this scope가 됩니다.
  • 단어와 단어 사이: return 0;을 return0;으로 붙이면 return0이라는 모르는 이름이 되어 error: 'return0' was not declared in this scope가 납니다.
  • #으로 시작하는 줄: 전처리 지시문은 한 줄에 하나씩 씁니다. #include <iostream> using namespace std;처럼 한 줄에 붙이면 뒷부분이 무시되어 cout을 찾지 못합니다.

대소문자 실수

3절에서 본 것처럼 Cout은 cout이 아닙니다.

Main은 더 교묘합니다. int Main()은 'Main이라는 이름의 다른 함수'로서 문법상 문제가 없으므로 컴파일은 통과합니다. 그리고 링크 단계에서 main을 찾지 못해 실패합니다(9절 마지막 예). Return, Int, #Include처럼 예약어의 첫 글자를 대문자로 쓰는 실수도 모두 에러입니다.

다음 다섯 문장 중 컴파일 에러가 나는 것을 모두 고르세요. (모두 #include <iostream>과 using namespace std;가 있는 main 안에 있다고 가정합니다.)

(나) cout   <<   "Hi"   <<   '\n'  ;
(다) co ut << "Hi" << '\n';
(라) COUT << "Hi" << '\n';
(마) cout
         << "Hi"

(다)와 (라)입니다. (다)는 단어 cout을 공백으로 쪼갰고, (라)는 대문자라서 다른 이름입니다. (가)·(나)는 기호 사이의 공백만 다를 뿐이고, (마)는 한 문장을 세 줄에 나눠 쓴 것이라 ;까지가 한 문장으로 읽혀 정상입니다. 셋 다 Hi를 출력합니다.

9컴파일 에러 읽는 법

컴파일 에러 메시지는 영어라서 처음에는 겁이 나지만, 형식이 정해져 있어서 읽는 법만 알면 대부분 위치와 원인을 바로 알려 줍니다. 아래 메시지는 모두 이 환경의 g++ 13이 실제로 낸 것입니다(파일 이름은 main.cpp).

예 1: 세미콜론 누락

#include <iostream>
using namespace std;

int main() {
    cout << "Hello" << '\n'
    return 0;
}
컴파일 에러
main.cpp: In function 'int main()':
main.cpp:5:28: error: expected ';' before 'return'
    5 |     cout << "Hello" << '\n'
      |                            ^
      |                            ;
    6 |     return 0;
      |     ~~~~~~
부분뜻
main.cpp: In function 'int main()':다음 에러가 main 함수 안에 있다는 안내
main.cpp파일 이름
5줄 번호
28칸 번호(그 줄의 몇 번째 글자인지)
error종류. error는 실행 파일을 만들 수 없음, warning은 만들 수는 있지만 수상함, note는 앞 메시지의 보충 설명
expected ';' before 'return'내용: return 앞에 ;가 있어야 한다
그 아래 줄들문제의 코드 줄과 위치 표시 ^. 여기서는 고칠 방법(;)까지 제안했습니다

컴파일러는 5줄 끝에서 문장이 끝나지 않은 채 6줄의 return을 만난 뒤에야 이상하다는 것을 압니다. 그래서 메시지에 다음 줄의 단어(return)가 등장합니다. 이번에는 g++가 위치를 5줄 끝으로 잡아 줬지만, 실수의 종류에 따라 위치가 그다음 줄로 표시되기도 합니다(바로 아래 예 2). 에러가 가리키는 줄에 이상이 없으면 바로 앞줄의 끝을 보세요.

예 2: 닫는 따옴표 누락 — 실수 하나, 에러 둘

#include <iostream>
using namespace std;

int main() {
    cout << "Hello << '\n';
    return 0;
}
컴파일 에러 (경고 줄은 생략)
main.cpp:5:13: error: missing terminating " character
    5 |     cout << "Hello << '\n';
      |             ^~~~~~~~~~~~~~~
main.cpp: In function 'int main()':
main.cpp:6:5: error: expected primary-expression before 'return'
    6 |     return 0;
      |     ^~~~~~

첫 에러는 '닫는 "가 없다'입니다. 컴파일러는 그 줄의 "부터 끝까지를 깨진 문자열로 보고 버립니다. 그러면 cout << 뒤에 아무 값도 없는 채로 return을 만나게 되어 두 번째 에러('return 앞에 값이 와야 한다')가 생깁니다. primary-expression은 '값이 들어갈 자리' 정도로 이해하면 됩니다. 실수는 하나인데 에러는 둘이고, 첫 번째만 고치면 둘 다 사라집니다.

was not declared in this scope는 '그런 이름은 들어 본 적이 없다'는 뜻입니다. 이 메시지를 보면 ① 오타 ② 대소문자 ③ #include 누락 ④ std::나 using namespace std; 누락, 네 가지를 차례로 의심하세요.

필수 문제

[PCCE 기출문제] 1번 / 문자 출력 Lv.0빈칸채우기(PCCE)필수

주어진 코드의 빈칸을 채워 3, 2, 1을 한 줄에 하나씩 출력하고, 이어서 변수 message에 저장된 Let's go!를 출력하게 만드는 문제입니다.

연습 포인트: 문자열 안의 \n으로 줄 나누기, 상자(변수) 이름과 문자열 리터럴의 차이(10절). 이 노트를 시작하게 만든 바로 그 문제입니다.

힌트 1

출력 예시를 줄 단위로 보세요. 3, 2, 1이 서로 다른 줄에 있습니다. 줄을 바꾸는 글자를 어디에 몇 개 넣어야 할까요? 마지막 줄 Let's go!는 이미 message라는 상자에 들어 있습니다.

힌트 2

3, 2, 1은 문자열 하나 안에 \n을 넣어 "3\n2\n1"처럼 한 번에 출력할 수 있습니다. message는 따옴표 없이 cout << message로 출력합니다. "message"라고 쓰면 글자 message가 그대로 나옵니다.

풀이 코드와 해설
#include <iostream>
#include <string>
using namespace std;

int main() {
    string message = "Let's go!";

    cout << "3\n2\n1" << '\n';
    cout << message << '\n';
    return 0;
}
실행 결과
3
2
1
Let's go!

빈칸은 어디였을까: PCCE 기출은 사이트가 보여 주는 초기 코드에서 빈칸만 채우는 형식인데, 이 노트에서는 C++ 초기 코드를 직접 확인할 수 없었습니다. 같은 문제의 Java 정답 코드 구조로 보면 빈칸은 ① 3, 2, 1을 출력하는 자리("3\n2\n1")와 ② message를 출력하는 자리, 두 곳이었을 가능성이 높습니다. 화면의 빈칸 위치에 맞춰 채우세요. 초기 코드가 줄바꿈에 endl을 쓰고 있다면 그대로 둬도 출력은 같습니다.

  • "3\n2\n1": 문자열 하나에 줄바꿈이 두 개 들어 있어 3줄이 됩니다. 1 뒤의 줄바꿈은 그다음의 '\n'이 담당합니다. cout << 3 << '\n' << 2 << '\n' << 1 << '\n';처럼 나눠 써도 같은 결과입니다.
  • cout << message: 따옴표가 없으므로 상자에 든 Let's go!가 나옵니다.
  • Let's의 작은따옴표는 큰따옴표 문자열 안에 있으므로 이스케이프가 필요 없습니다(6절).

흔한 오답: cout << "message"는 message라는 글자를 출력합니다. "3 2 1"은 한 줄에 공백으로 출력되어 오답입니다. 'Let's go!'처럼 작은따옴표로 감싸면 안쪽의 '에서 문자 리터럴이 깨져 missing terminating ' character 컴파일 에러가 납니다.

힌트 2

풀이 코드와 해설

using namespace std;

}
실행 결과

\\\이스케이프의 시작 표시라서 두 번 써야 한 글자
