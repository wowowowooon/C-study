## Topics to teach (in this order; each normally becomes one or more numbered h3 sections)
1. 왜 함수인가: 반복 코드 제거, 이름 붙이기, 따로 테스트하기.
2. 함수 정의: 반환형 이름(매개변수) { 본문; return 값; }, 호출, 인자(argument) vs 매개변수(parameter), void, 여러 개의 return(early return), 반환 없이 끝나는 non-void 함수 = 정의되지 않은 동작(-Wreturn-type 경고를 실제로).
3. 호출의 흐름과 콜 스택: 호출 → 매개변수에 값 복사 → 본문 → 반환 → 돌아옴, 스택 프레임 그림(지역 변수, 반환 주소). .emb: 스타트업 파일의 스택 크기, 스택 오버플로.
4. 선언(프로토타입)과 정의: 사용 전에 알아야 한다, main 아래에 정의하려면 위에 선언. 헤더(.h)/소스(.cpp) 나누기 맛보기(.emb: HAL 드라이버 gpio.h/gpio.c).
5. 값 전달: 복사본을 바꿔도 원본은 그대로 — swap 실패 예제(실행 결과로).
6. 참조 전달(&): 별명, swap 성공, 참조로 여러 값 돌려주기, const 참조(const vector<int>&, const string&) — 큰 데이터 복사 방지(시간 초과 원인), 수정 불가 보장.
7. 변수의 범위(scope)와 수명(lifetime): 지역/전역/정적(static) 지역 변수, 가려짐(shadowing), 전역 변수 남용의 문제, 코딩테스트에서 큰 배열을 전역에 두는 관행과 이유(스택 크기), static 지역 변수(호출 사이 값 유지).
8. 함수 오버로딩, 기본 인자 — 간단히.
9. 재귀 기초: 자기 자신을 호출, 종료 조건 필수, 팩토리얼/거듭제곱/자릿수 합 재귀, trace(스택이 쌓이고 풀리는 과정), 재귀 vs 반복, 피보나치 재귀가 느린 이유(호출 트리와 호출 횟수 폭발 — 호출 횟수를 실제로 세어 출력) → 반복/메모이제이션(25장 예고), 깊은 재귀 → 스택 오버플로.
10. 유클리드 호제법 gcd(재귀/반복), lcm = a / gcd(a, b) * b(오버플로를 피하는 순서), std::gcd(C++17 <numeric>).
11. 프로그래머스 solution과 도우미 함수: solution 밖에 isPrime 같은 함수 만들기, 전역 변수를 쓰면 solution 안에서 매번 초기화하는 습관(채점기가 solution을 여러 번 부를 수 있다고 가정).
12. 좋은 함수 습관: 한 가지 일, 이름, 매개변수 개수, 부작용 줄이기.

- 재귀 종료 조건 누락
