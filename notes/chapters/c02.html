변수와 자료형, 입력Variables, types and input

이 챕터를 마치면: ① 값을 담을 변수를 알맞은 자료형으로 선언·초기화하고, 대입이 메모리에서 어떻게 일어나는지 설명할 수 있습니다. ② int 오버플로, 정수 나눗셈, 실수 오차처럼 '예제는 맞는데 제출하면 틀리는' 자료형 함정을 피할 수 있습니다. ③ cin, getline, C의 scanf/printf로 입력을 읽고 원하는 형식으로 출력할 수 있습니다. ④ 프로그래머스 함수형(solution) 템플릿을 읽고 첫 함수형 문제를 풀 수 있습니다.

1이 챕터에서 배울 것과 이유

1장에서는 string str;, int a;를 '값을 담는 상자'라고만 부르고 넘어갔습니다. 이 장에서는 그 상자의 정체인 변수(variable)와, 상자의 종류를 정하는 자료형(data type)을 정확히 배웁니다. 이어서 입력을 읽는 방법을 getline과 C의 scanf까지 넓히고, 프로그래머스 문제 대부분이 쓰는 함수형 템플릿을 읽는 법으로 마무리합니다.

코딩테스트: 모든 문제는 '값을 받아서 변수에 담고, 계산해서, 답을 내보내는' 일입니다. 자료형을 잘못 고르면 예제는 통과하는데 제출하면 틀립니다. 흔한 원인이 세 가지 있습니다. int 범위(약 21억)를 넘는 계산, 정수 나눗셈으로 사라지는 소수점, cin >> 다음에 쓴 getline이 빈 줄을 읽는 문제입니다. 이 장에서 세 가지 모두 원인부터 짚습니다.

임베디드: 펌웨어의 변수는 MCU RAM의 실제 칸이고, 자료형의 크기는 곧 RAM 사용량과 계산 속도입니다. STM32F103C8의 RAM은 20 KB뿐이고, 센서 값·타이머 카운터·레지스터 값은 모두 비트 수가 정해진 정수입니다. 'int가 몇 바이트인가', '값이 넘치면 어떻게 되는가'를 정확히 아는 것이 제어 코드 버그를 막는 출발점입니다.

먼저 복습할 것: 1장의 cout << 출력, cin >>이 공백에서 끊긴다는 점, 컴파일 에러 메시지의 파일:줄:칸 읽는 법. 이 장의 실행 결과와 메시지는 모두 64비트 리눅스(Ubuntu)의 g++/gcc 13에서 실제로 실행해 얻은 것입니다. 따로 적지 않으면 옵션은 C++가 -std=c++17 -O1 -Wall -Wextra, C가 -std=c11 -O1 -Wall -Wextra입니다.

2변수: 이름 붙은 메모리 칸

프로그램이 실행되는 동안 값은 메모리(RAM)에 저장됩니다. 메모리는 1바이트짜리 칸이 길게 늘어선 것이고, 칸마다 번호가 붙어 있습니다. 이 번호를 주소(address)라고 합니다. 변수는 메모리의 칸 몇 개를 빌려서 이름을 붙인 것입니다. 사람은 '0x1000번 칸' 대신 speed라는 이름으로 그 칸을 읽고 씁니다.

#include <iostream>
using namespace std;

int main() {
    int speed = 30;
    cout << speed << '\n';
    speed = 45;
    cout << speed << '\n';
    return 0;
}
실행 결과
30
45

한 줄씩 보겠습니다.

  • int speed = 30; — 변수를 만드는 문장입니다.
    • int: 자료형입니다. 이 칸에 어떤 종류의 값(정수)을 담을지, 칸이 몇 바이트인지(이 노트의 환경에서 4바이트)를 정합니다.
    • speed: 변수 이름입니다. 이후에는 이 이름으로 칸을 가리킵니다.
    • = 30: 칸을 만들면서 처음 넣을 값입니다.
    변수를 만드는 것을 선언(declaration), 만들면서 첫 값을 넣는 것을 초기화(initialization)라고 합니다.
  • cout << speed — 따옴표가 없으므로 이름 speed가 가리키는 칸의 값 30을 꺼내 출력합니다. 1장에서 본 "message"(글자 그대로)와 message(변수의 값)의 차이와 같습니다.
  • speed = 45; — 이미 있는 칸에 새 값을 넣습니다. 이것을 대입(assignment)이라고 합니다. 앞에 int가 없다는 점이 중요합니다. int를 붙이면 '같은 이름의 칸을 하나 더 만들어라'라는 뜻이 되어 에러가 납니다(아래에서 봅니다). 원래 있던 30은 덮어써져서 사라집니다.
0x100030speed

int speed = 30; 직후. 주소 0x1000은 설명을 위해 고른 값이고, 실제 주소는 실행할 때마다 달라질 수 있습니다. int는 4바이트이므로 실제로는 0x1000~0x1003의 네 칸을 함께 씁니다.

0x100045speed

= 는 '같다'가 아닙니다

수학에서 x = x + 1은 성립할 수 없는 식입니다. C++의 =는 '같다'가 아니라 대입 연산자(assignment operator)이고, 뜻은 "오른쪽을 먼저 계산하고, 그 결과를 왼쪽 이름의 칸에 넣어라"입니다. '같은가?'를 묻는 기호는 ==이고 3장에서 배웁니다.

#include <iostream>
using namespace std;

int main() {
    int x = 5;
    x = x + 1;
    cout << x << '\n';
    x = x * 2;
    cout << x << '\n';
    return 0;
}
실행 결과
6
12

*는 곱셈입니다. 사칙연산 + - * /는 이 장에서 맛보기로만 쓰고 3장에서 정식으로 배웁니다. 각 줄이 실행될 때 일어나는 일을 표로 따라가 보겠습니다.

실행한 줄① 오른쪽 계산 (읽기)② 왼쪽 칸에 저장 (쓰기)x의 값
int x = 5;—x ← 55
x = x + 1;x의 현재 값 5를 읽어 5 + 1 = 6x ← 66
x = x * 2;x의 현재 값 6을 읽어 6 * 2 = 12x ← 1212

핵심은 순서입니다. 오른쪽의 x는 '지금 칸에 든 값'을 읽고, 계산이 끝난 뒤에야 왼쪽 칸에 새 값을 씁니다. 그래서 x = x + 1은 'x를 1 늘려라'라는 뜻이 됩니다.

대입의 왼쪽에는 값을 넣을 수 있는 칸(변수)이 와야 합니다. 5 = x;처럼 쓰면 g++는 error: lvalue required as left operand of assignment라고 알려 줍니다. lvalue(엘밸류)는 '값을 넣을 수 있는 칸'을 가리키는 용어이고, 숫자 5는 칸이 아니라 값이므로 왼쪽에 올 수 없습니다.

변수 이름 규칙

변수 이름처럼 프로그래머가 붙이는 이름을 식별자(identifier)라고 합니다. 규칙은 다음과 같습니다.

  • 영문자, 숫자, 밑줄(_)만 쓸 수 있습니다. 공백과 -는 안 됩니다. motor-rpm은 'motor 빼기 rpm'으로 읽힙니다.
  • 숫자로 시작할 수 없습니다. 2nd는 안 되고 second, num2는 됩니다.
  • 예약어(keyword)는 쓸 수 없습니다. int, double, return, if, for, const, true처럼 C++가 이미 쓰고 있는 단어입니다.
  • 대소문자를 구분합니다. score와 Score는 서로 다른 이름입니다.
  • 권장: a, tmp2보다 speed, student_count처럼 뜻이 보이는 이름을 쓰세요. 밑줄 두 개(__)나 '밑줄 + 대문자'로 시작하는 이름은 컴파일러와 표준 라이브러리용으로 예약되어 있으니 피하세요.
#include <iostream>
using namespace std;

int main() {
    int 2nd = 5;
    return 0;
}
컴파일 에러
main.cpp:5:9: error: expected unqualified-id before numeric constant
    5 |     int 2nd = 5;
      |         ^~~

unqualified-id는 대략 '이름'을 뜻합니다. 메시지는 '이름이 와야 할 자리(5번 줄 9번째 칸)에 숫자가 왔다'는 뜻입니다. 예약어를 이름으로 쓰면(int return = 5;) expected unqualified-id before 'return', 이름에 공백을 넣으면(int my score = 90;) expected initializer before 'score'가 나옵니다. 메시지는 달라도 원인은 '이름 규칙 위반'입니다.

다음 중 변수 이름으로 쓸 수 없는 것을 모두 고르세요.
speed2, 2speed, motor_rpm, motor-rpm, int, Int, _count
답 보기

2speed(숫자로 시작), motor-rpm(-는 빼기 연산자), int(예약어)입니다. Int는 대소문자가 달라 예약어가 아니므로 문법상 허용되지만, 읽는 사람을 헷갈리게 하니 쓰지 마세요. _count는 '밑줄 + 소문자'라 함수 안의 변수 이름으로는 허용됩니다.

선언하기 전에 사용하기. C++는 코드를 위에서 아래로 읽습니다. 변수는 선언한 줄 아래에서만 쓸 수 있습니다.
#include <iostream>
using namespace std;

int main() {
    total = 100;
    int total = 0;
    cout << total << '\n';
    return 0;
}
컴파일 에러
main.cpp:5:5: error: 'total' was not declared in this scope
    5 |     total = 100;
      |     ^~~~~

'5번 줄 시점에서 total이라는 이름은 아직 선언되지 않았다'는 뜻입니다. scope(범위)는 이름이 통하는 영역을 말하며 8장에서 자세히 다룹니다. 같은 메시지는 대소문자를 틀렸을 때도 나옵니다. int score = 90;로 만들고 cout << Score;라고 쓰면 error: 'Score' was not declared in this scope; did you mean 'score'?처럼 g++가 비슷한 이름을 제안해 줍니다.

같은 이름을 두 번 선언하기. 값을 바꾸려는 줄에 습관처럼 int를 또 붙이는 실수입니다.
#include <iostream>
using namespace std;

int main() {
    int speed = 10;
    int speed = 20;
    cout << speed << '\n';
    return 0;
}
컴파일 에러
main.cpp:6:9: error: redeclaration of 'int speed'
    6 |     int speed = 20;
      |         ^~~~~
main.cpp:5:9: note: 'int speed' previously declared here

redeclaration은 '다시 선언했다'는 뜻이고, note 줄이 처음 선언한 위치(5번 줄)를 알려 줍니다. 값을 바꾸려면 int 없이 speed = 20;이라고 대입하면 됩니다.

3초기화하지 않은 변수는 쓰레기 값

1장의 cin >> a >> b 추적 표에서, 입력을 읽기 전의 a와 b를 '?'로 표시했습니다. 초기값 없이 선언만 한 변수에는 무엇이 들어 있을까요?

#include <iostream>
using namespace std;

int main() {
    int x;
    cout << x << '\n';
    return 0;
}
컴파일 경고
main.cpp:6:18: warning: 'x' is used uninitialized [-Wuninitialized]
main.cpp:5:9: note: 'x' was declared here

컴파일은 됩니다(에러가 아니라 경고). 이 노트의 환경에서 같은 코드를 컴파일 옵션만 바꿔 세 번씩 실행했더니 이렇게 나왔습니다.

컴파일 옵션1번째2번째3번째
-O0 (최적화 없음)327653276732766
-O1 (최적화)000

-O0 쪽은 다시 실행하면 또 다른 값이 나옵니다. 같은 프로그램인데 실행할 때마다, 옵션에 따라 결과가 다릅니다.

함수 안에서 선언한 변수를 지역 변수(local variable)라고 합니다. 지역 변수의 칸은 직전에 다른 코드가 쓰던 메모리일 수 있는데, C++는 속도를 위해 그 칸을 청소하지 않습니다. 그래서 남아 있던 의미 없는 값, 흔히 말하는 쓰레기 값(garbage value)이 보입니다.

정확히 말하면 초기화하지 않은 변수의 값을 읽는 것은 정의되지 않은 동작(undefined behavior, 줄여서 UB)입니다. 정의되지 않은 동작이란 C++ 표준이 '이렇게 하면 결과가 어떻게 되는지 아무것도 정하지 않는다'고 선언한 상황입니다. 엉뚱한 값이 나올 수도, 매번 다를 수도, 위의 -O1처럼 0이 나올 수도 있습니다. 0이 나왔다고 안전한 것이 아닙니다. 컴파일러나 옵션, 주변 코드가 바뀌면 결과가 바뀝니다. 내 컴퓨터에서는 맞는데 채점 서버에서 틀리는 대표적인 원인입니다.

핵심 정리 변수는 선언할 때 바로 초기화하세요. int count = 0;, double sum = 0.0;, bool found = false;처럼요. 단, string s;는 예외적으로 빈 문자열("")로 시작하는 것이 보장됩니다. string은 라이브러리가 만든 타입이라 만들어질 때 스스로 정리하기 때문입니다(10장의 생성자). 쓰레기 값이 생기는 것은 int, double, char, bool 같은 기본 자료형입니다.
한 줄에 여러 변수를 선언할 수 있지만 초기화는 각자 따로입니다. int a, b = 0;은 b만 0이고 a는 초기화되지 않습니다. 이 상태로 a를 출력하면 g++는 warning: 'a' is used uninitialized를 냅니다. 헷갈리지 않도록 이 노트는 한 줄에 변수 하나만 선언합니다.

전역 변수는 0에서 시작합니다

모든 함수의 바깥(main보다 위)에 선언한 변수를 전역 변수(global variable)라고 합니다. 전역 변수는 초기값을 쓰지 않아도 0으로 시작하는 것이 표준으로 보장됩니다.

#include <iostream>
using namespace std;

int count_g;      // 전역 변수: 함수 바깥에 선언
double ratio_g;   // 실수 전역 변수는 0.0

int main() {
    cout << count_g << '\n';
    cout << ratio_g << '\n';
    return 0;
}
실행 결과
0
0

그렇다고 '초기화가 귀찮으니 전부 전역으로' 만들면 안 됩니다. 어디서든 값을 바꿀 수 있어서 버그를 찾기 어려워집니다(8장). 이 장의 코드는 모두 지역 변수를 쓰고, 초기화를 직접 합니다.

변수가 사는 곳은 종류마다 다릅니다. 지역 변수는 스택(stack)이라는 영역에 함수가 실행될 때 자리를 잡고, 함수가 끝나면 반납됩니다. 반납된 자리는 청소되지 않으니 다음에 그 자리를 받은 변수에 이전 값이 보입니다. 이것이 쓰레기 값의 정체입니다. 전역 변수는 다릅니다. 초기값이 있는 전역 변수(int g = 5;)는 .data 영역에, 초기값이 없거나 0인 전역 변수는 .bss 영역에 놓입니다. STM32 프로젝트의 스타트업 코드(startup_stm32f103xx.s 같은 파일의 Reset_Handler)는 main을 부르기 전에 .data의 초기값을 Flash에서 RAM으로 복사하고, .bss를 0으로 채웁니다. 전역 변수가 0에서 시작하는 이유가 바로 이것입니다. 빌드 끝에 arm-none-eabi-size가 출력하는 text / data / bss 숫자가 이 영역들의 크기입니다. 메모리 영역은 9장, MCU 메모리 맵은 30장에서 자세히 봅니다.

int g;

int main() {

    int b = 0;
    string s;
    cout << g << b << s << a << '\n';

}

4기본 자료형과 크기

자료형은 칸의 크기와, 칸에 든 비트를 어떻게 해석할지를 정합니다. 같은 4바이트라도 int로 읽으면 정수, float로 읽으면 실수입니다. C++에 처음부터 들어 있는 기본 자료형(fundamental type)이 각각 몇 바이트인지 직접 확인해 보겠습니다. sizeof(자료형)은 그 자료형이 차지하는 바이트 수를 알려 줍니다.

  • long은 피하고 long long을 쓰세요. long은 64비트 리눅스에서는 8바이트지만 64비트 윈도우와 32비트 ARM에서는 4바이트입니다. 코딩테스트에서 큰 정수에 long long을 쓰는 이유입니다.
  • char의 부호도 정해져 있지 않습니다. x86의 g++에서 char는 -128 ~ 127이지만, ARM 리눅스(라즈베리 파이, 젯슨)의 g++에서는 0 ~ 255입니다. 이렇게 컴파일러가 정하도록 표준이 맡겨 둔 부분을 구현 정의(implementation-defined)라고 합니다.
  • unsigned(부호 없는)를 붙이면 음수를 포기하는 대신 양수 범위가 두 배가 됩니다. unsigned int는 줄여서 unsigned라고도 씁니다. 음수가 나올 수 있는 계산에 unsigned를 쓰면 사고가 나므로(5절) 코딩테스트에서는 특별한 이유가 없으면 쓰지 않습니다.

그래서 펌웨어에서는 크기가 정확히 고정된 int8_t, uint16_t, int32_t 같은 타입(<cstdint>, C에서는 <stdint.h>)을 씁니다. 이름의 숫자가 비트 수이고, u가 붙으면 unsigned입니다. 29장에서 자세히 다룹니다.

5정수 오버플로와 long long

int 칸은 32비트라서 2147483647보다 큰 수를 담을 수 없습니다. 담을 수 있는 범위를 넘어서는 것을 오버플로(overflow)라고 합니다. 최댓값에 1을 더하면 어떻게 될까요?

#include <climits>
#include <iostream>
using namespace std;

int main() {
    int x = INT_MAX;
    cout << x << '\n';
    x = x + 1;  // 부호 있는 정수 오버플로: 정의되지 않은 동작
    cout << x << '\n';
    return 0;
}
이 노트 환경에서 나온 결과 (보장되지 않음)

-2147483648

최댓값 다음이 최솟값으로 넘어간 것처럼 보입니다. 실제로 많은 CPU는 이렇게 계산합니다. 하지만 C++ 표준은 부호 있는 정수(signed integer)의 오버플로를 정의되지 않은 동작으로 정해 두었습니다. '최솟값으로 넘어간다'는 보장이 없다는 뜻이고, 더 중요한 것은 컴파일러가 '오버플로는 절대 일어나지 않는다'고 가정하고 코드를 바꿔도 된다는 점입니다. 다음 예가 그 결과를 보여 줍니다.

>는 '왼쪽이 더 큰가?'를 묻는 비교 연산자이고(3장), 출력 1은 '참', 0은 '거짓'이라는 뜻입니다. x + 1을 출력하면 음수가 나오는데, 'x + 1이 x보다 큰가?'라는 질문에는 참이라고 답합니다. 앞뒤가 맞지 않습니다. 컴파일러가 'x + 1 > x는 오버플로가 없다면 항상 참'이라고 판단해서 비교 자체를 1로 바꿔 버렸기 때문입니다. 오버플로가 일어난 프로그램은 이렇게 논리가 무너진 채로 돌아갈 수 있습니다.

참고로 cout << 2147483647 + 1;처럼 숫자를 직접 쓰면, g++가 컴파일할 때 미리 계산해 보고 warning: integer overflow in expression of type 'int' results in '-2147483648' [-Woverflow] 경고를 냅니다. 하지만 위 예제처럼 값이 변수에 있거나 입력으로 들어오면 컴파일러는 값을 미리 알 수 없으므로 경고도 없습니다. 오버플로는 대부분 조용히 일어납니다.

unsigned는 0으로 돌아갑니다 (정의된 동작)

부호 없는 정수(unsigned)는 다릅니다. 범위를 넘으면 2³²(unsigned int의 경우)로 나눈 나머지가 되도록 표준이 정해 두었습니다. 자동차 주행거리계가 999999 다음에 000000이 되는 것과 같습니다.

#include <climits>
#include <iostream>
using namespace std;

int main() {
    unsigned int u = UINT_MAX;
    u = u + 1;
    cout << u << '\n';
    unsigned int v = 0;
    v = v - 1;
    cout << v << '\n';
    unsigned int w = 3;
    w = w - 5;
    cout << w << '\n';
    return 0;
}
실행 결과
0
4294967295
4294967294

마지막 줄을 보세요. 3 - 5가 -2가 아니라 4294967294입니다. unsigned에는 음수가 없기 때문입니다. 결과가 정의되어 있으니 버그가 아닌 것처럼 보이지만, 음수를 기대한 코드에서는 명백한 버그입니다. 6장에서 배울 vector의 size()가 unsigned를 돌려주기 때문에 v.size() - 1에서 같은 사고가 납니다.

unsigned의 '정의된 랩어라운드(wrap-around)'는 펌웨어에서 일부러 이용하기도 합니다. STM32 HAL의 HAL_GetTick()은 부팅 후 지난 시간을 밀리초 단위의 uint32_t(unsigned 32비트)로 돌려주는데, 약 49.7일(2³² ms)이 지나면 0으로 돌아갑니다. 그래도 경과 시간을 now - start처럼 unsigned 뺄셈으로 구하면, 중간에 0으로 돌아간 경우에도 올바른 값이 나옵니다. 
#include <iostream>
using namespace std;

int main() {
    unsigned int start = 4294967290u;  // 넘치기 직전에 기록한 시각
    unsigned int now = 4u;             // 0으로 돌아간 뒤의 시각
    unsigned int elapsed = now - start;
    cout << elapsed << '\n';
    return 0;
}
실행 결과
10
4294967290에서 4294967295까지 5번, 0으로 넘어가서 4까지 5번, 합쳐서 10입니다. 시각을 int에 저장했다면 넘치는 순간 정의되지 않은 동작이 되었을 것입니다. STM32 타이머의 카운터 레지스터(CNT)가 설정한 최댓값에 도달한 다음 0으로 돌아가는 것도 같은 모습입니다.

코딩테스트에서 long long이 필요한 순간

코딩테스트에서 오버플로는 '예제는 맞는데 제출하면 틀리는' 단골 원인입니다. 예제는 작은 숫자라 문제가 없고, 숨겨진 테스트의 큰 숫자에서만 넘치기 때문입니다. 다음 경우에는 long long을 쓰세요.

  • 답이나 중간 계산이 약 21억(2.1×10⁹)을 넘을 수 있을 때. 대표적으로 두 수의 곱(10⁹ × 10⁹ = 10¹⁸), 많은 수의 합(10⁹짜리 값 10⁵개를 더하면 10¹⁴).
  • 프로그래머스 템플릿의 반환형이 long long solution(...)일 때. '답이 int를 넘을 수 있다'는 힌트입니다.
#include <iostream>
using namespace std;

int main() {
    long long a = 1000000000;
    long long b = 1000000000;
    cout << a * b << '\n';
    long long c = 1000000000LL * 1000000000;
    cout << c << '\n';
    return 0;
}

a * b는 int × int라 int로 계산되고, 2,500,000,000은 int 최댓값 2,147,483,647보다 커서 오버플로(정의되지 않은 동작)가 일어납니다. 이번에는 값이 변수에 들어 있어서 컴파일러 경고도 없습니다. 고치는 방법은 a와 b를 처음부터 long long으로 선언하는 것입니다. 9절에서 배울 static_cast<long long>(a) * b도 같은 효과가 있습니다.

6실수: double과 float

소수점이 있는 수, 즉 실수(real number)는 부동소수점(floating point) 방식으로 저장합니다. 기본은 double입니다. float는 크기가 절반(4바이트)이지만 정밀도가 훨씬 낮습니다. 실수에는 정수에 없는 함정이 하나 있습니다.

#include <iostream>
using namespace std;

int main() {
    double a = 0.1 + 0.2;
    cout << a << '\n';
    cout << (a == 0.3) << '\n';
    return 0;
}
실행 결과
0.3
0

==는 '같은가?'를 묻는 비교 연산자입니다(3장). 0.3이라고 출력해 놓고 0.3과 같으냐는 질문에는 거짓(0)이라고 답합니다. cout은 기본적으로 유효숫자 6자리까지만 보여 주기 때문에 차이가 가려진 것입니다. 자릿수를 늘려 실제로 저장된 값을 보겠습니다. <iomanip> 헤더의 setprecision(n)은 출력할 유효숫자 개수를 정합니다.

#include <iomanip>
#include <iostream>
using namespace std;

int main() {
    cout << setprecision(17);
    cout << 0.1 + 0.2 << '\n';
    cout << 0.3 << '\n';
    cout << 0.1 << '\n';
    return 0;
}
실행 결과
0.30000000000000004
0.29999999999999999
0.10000000000000001

0.1조차 정확히 0.1이 아닙니다. 이유는 컴퓨터가 실수를 2진수로 저장하기 때문입니다. 10진수에서 1/3 = 0.3333…이 끝없이 이어지듯, 10진수 0.1을 2진수로 바꾸면 0.000110011001100…₂처럼 끝없이 이어집니다. double은 정해진 비트 수(유효숫자 약 15~16자리)에서 잘라 가장 가까운 값을 저장하므로 아주 작은 오차가 생깁니다. 0.1 + 0.2를 계산한 결과와 0.3을 바로 저장한 값은 오차가 서로 달라서, 값이 정확히 같은지 묻는 ==에서는 다르다고 나옵니다.

실수는 ==로 비교하지 마세요. '차이가 아주 작으면 같다고 본다'는 식으로 비교해야 합니다(예: 두 값의 차이의 절댓값이 0.000000001보다 작으면 같다). 이렇게 쓰려면 절댓값 함수와 if가 필요하므로 3장과 4장에서 완성합니다. 그리고 정수로 풀 수 있는 문제는 처음부터 정수로 푸는 것이 가장 안전합니다.

float는 정밀도가 낮습니다

using namespace std;

    cout << setprecision(20);
    cout << f << '\n';
    cout << d << '\n';
    float big = 16777216.0f;
    big = big + 1.0f;
    cout << big << '\n';
    return 0;

float에 저장된 0.1은 소수점 아래 9번째 자리부터, double에 저장된 0.1은 18번째 자리부터 진짜 0.1과 달라집니다. 더 놀라운 것은 마지막 줄입니다. float는 유효숫자를 2진수 24자리만 담을 수 있어서 2²⁴ = 16,777,216을 넘으면 1 단위의 차이를 표현하지 못합니다. 16777216에 1을 더해도 16777216 그대로입니다. 그래서 코딩테스트에서는 실수가 필요하면 항상 double을 씁니다.

이 마지막 줄은 실제 펌웨어 버그의 형태 그대로입니다. 1 ms마다 t = t + 1.0f;로 float 변수 t에 시간을 누적하면 16,777,216 ms(약 4.7시간) 뒤부터 시간이 더 이상 늘지 않습니다. 그런데도 펌웨어는 float를 많이 씁니다. STM32F4 같은 Cortex-M4F의 FPU(부동소수점 연산 장치)는 단정밀도(float)만 하드웨어로 계산하고, double 연산은 소프트웨어 라이브러리가 흉내 내므로 몇 배에서 수십 배 느립니다. 주의할 점은 접미사입니다. float y = x * 0.5;에서 0.5는 double 리터럴이라 계산 전체가 double로 바뀝니다. 펌웨어에서는 0.5f처럼 f를 붙이세요. 31장에서 고정소수점과 함께 다시 봅니다.

7char 맛보기: 문자는 사실 숫자입니다

char는 문자 하나를 담는 1바이트 자료형입니다. 그런데 메모리에는 글자 모양이 아니라 숫자가 저장됩니다. 어떤 숫자가 어떤 글자인지는 ASCII(아스키) 표라는 약속으로 정해져 있습니다.

#include <iostream>
using namespace std;

int main() {
    char c = 'A';
    int code = c;
    cout << c << '\n';
    cout << code << '\n';
    cout << c + 1 << '\n';
    char next = c + 1;
    cout << next << '\n';
    return 0;
}
실행 결과

B
  • char c = 'A'; — c 칸에는 실제로 숫자 65가 저장됩니다. ASCII에서 'A'는 65입니다.
  • int code = c; — 같은 65를 int 칸에 복사했습니다. cout은 char는 글자로, int는 숫자로 출력하므로 65가 나옵니다.
  • c + 1 — char에 정수를 더하면 결과는 int입니다. 그래서 글자 B가 아니라 숫자 66이 나옵니다. 계산할 때 작은 정수 타입이 int로 바뀌는 규칙(정수 승격)은 29장에서 자세히 봅니다.
  • char next = c + 1; — 66을 char 칸에 넣으면 다시 글자로 출력되어 B가 됩니다.

외워 둘 ASCII 값은 몇 개 안 됩니다. 'A' = 65(대문자는 'Z' = 90까지 연속), 'a' = 97(소문자도 연속), '0' = 48(숫자 문자도 '9' = 57까지 연속), ' '(공백) = 32. 글자 '0'은 숫자 0이 아니라 48이라는 점이 중요합니다. 이 성질을 이용한 문자 계산은 7장에서 본격적으로 다룹니다.

  • string empty; — 3절에서 본 대로 빈 문자열로 시작합니다. 대괄호 사이에 아무것도 출력되지 않았습니다.

숫자의 +와 문자열의 +

같은 +라도 타입에 따라 뜻이 다릅니다. 15절의 PCCE 문제가 바로 이 차이를 묻습니다.

#include <iostream>
#include <string>
using namespace std;

int main() {
    int a = 3;
    string s = "3";
    cout << a + 10 << '\n';
    cout << s + "10" << '\n';
    return 0;
}
실행 결과
13

a는 int라서 a + 10은 덧셈 13입니다. s는 string이라서 s + "10"은 글자 "3" 뒤에 글자 "10"을 붙인 "310"입니다. 화면에는 둘 다 숫자처럼 보이지만, 310은 숫자 삼백십이 아니라 '3', '1', '0' 세 글자입니다. 변수의 타입이 연산의 뜻을 정한다는 것, 이것이 이 장 전체의 주제입니다.

그렇다면 string 변수 없이 "3" + "10"이라고 쓰면 어떨까요?

#include <iostream>
#include <string>
using namespace std;

int main() {

    return 0;
}

      |                ~~~ ^ ~~~~
      |                |     |
      |                |     const char [3]

#include <iostream>
#include <string>
using namespace std;

int main() {
    string a = string("3") + "10";
    string s = "abc";
    string t = s + "x" + "y";
    string u = s + '!';
    cout << a << ' ' << t << ' ' << u << '\n';
    return 0;
}

  • s + "x" + "y" — +는 왼쪽부터 두 개씩 계산합니다. s + "x"가 먼저 string "abcx"가 되고, 거기에 "y"를 붙입니다.
  • s + '!' — string에 char 하나를 붙이는 것도 됩니다.

숫자 + 문자열 리터럴은 이어 붙이기가 아닙니다. 자바나 파이썬에서 a + " + "로 문자열을 만들던 습관이 있다면 특히 위험합니다. C++에서는 에러도 경고도 없이 엉뚱하게 동작합니다.

(다) string d = "Hi"; d = d + '?';
(라) string e = "Robot" + string("Arm");

9형 변환: 타입이 바뀌는 순간

서로 다른 타입의 값을 섞어 계산하거나 다른 타입의 칸에 넣으면 값의 타입이 바뀝니다. 이것을 형 변환(type conversion)이라고 합니다. 컴파일러가 알아서 하는 암시적 변환(implicit conversion)과, 프로그래머가 직접 지시하는 명시적 변환(explicit conversion, 캐스트 cast)이 있습니다.

암시적 변환: int ↔ double

#include <iostream>
using namespace std;

int main() {
    int n = 7;
    double d = n;
    cout << d << '\n';
    int a = 3.7;
    int b = -3.7;
    double x = 2.99;
    int c = x;
    cout << a << ' ' << b << ' ' << c << '\n';
    return 0;
}
실행 결과
7
3 -3 2
  • double d = n; — int 7이 double 7.0으로 바뀌어 저장됩니다. 값은 그대로입니다. 출력이 7인 것은 6절에서 본 대로 cout이 7.0을 그렇게 보여 주기 때문입니다.
  • int a = 3.7; — double을 int 칸에 넣으면 소수 부분을 버립니다(truncation). 반올림이 아니라서 2.99도 2가 됩니다.
  • int b = -3.7; — 음수도 0 쪽으로 버립니다. -4가 아니라 -3입니다.
int에 3.7을 넣으면 3이 되는데, 컴파일러는 아무 말도 하지 않습니다. -Wall -Wextra를 켜도 이 변환에는 경고가 나오지 않습니다(-Wconversion이라는 옵션을 따로 켜야 경고합니다). 소수점이 사라지는 것은 버그일 때가 많으니, 실수를 정수 칸에 넣는 코드를 쓸 때마다 '버려도 되는가'를 스스로 확인하세요.
중괄호로 초기화하면(int speed{3.7};) 값이 잘려 나가는 변환을 컴파일러가 에러로 막아 줍니다. 이런 변환을 축소 변환(narrowing conversion)이라고 합니다. 
#include <iostream>
using namespace std;

int main() {
    int speed{3.7};
    cout << speed << '\n';
    return 0;
}
컴파일 에러
main.cpp:5:15: error: narrowing conversion of '3.7000000000000002e+0' from 'double' to 'int' [-Wnarrowing]
메시지에 3.7이 3.7000000000000002e+0으로 찍힌 것도 보세요. 6절에서 본 대로 3.7도 2진수로는 정확히 저장되지 않습니다. 이 노트는 익숙한 = 초기화를 계속 쓰지만, 이런 방법이 있다는 것은 알아 두세요.

정수끼리 나누면 정수

형 변환에서 가장 많이 틀리는 곳은 나눗셈입니다.

#include <iomanip>
#include <iostream>
using namespace std;

int main() {
    double r = 7 / 2;
    cout << r << '\n';
    cout << fixed << setprecision(1) << r << '\n';
    return 0;
}
실행 결과
3
3.0

r이 double인데도 3.5가 아니라 3.0입니다. double r = 7 / 2;는 두 단계로 실행됩니다.

  1. 7 / 2를 계산합니다. 7도 int, 2도 int이므로 결과도 int입니다. int 나눗셈은 몫만 남기고 소수점 아래를 버리므로 3입니다(나눗셈 규칙은 3장에서 자세히 봅니다).
  2. int 3을 double 3.0으로 바꿔 r에 저장합니다.

나눗셈은 대입보다 먼저, int끼리 이미 끝났습니다. 왼쪽 칸이 double이라는 사실은 오른쪽 계산에 아무 영향을 주지 않습니다. 5절에서 long long big = 1000000000 * 1000000000;이 넘친 것과 똑같은 원리입니다. 기본 출력에서는 3.0이 3으로 보이므로, 소수점 한 자리까지 보이게 출력해서 확인했습니다.

static_cast로 직접 바꾸기

실수 나눗셈을 하려면 계산하기 전에 한쪽을 double로 바꿔야 합니다. static_cast<바꿀 타입>(값)이 C++에서 권장하는 명시적 변환입니다.

#include <iostream>
using namespace std;

int main() {
    int a = 7;
    int b = 2;
    cout << a / b << '\n';
    cout << static_cast<double>(a) / b << '\n';
    cout << static_cast<double>(a / b) << '\n';
    cout << 7.0 / 2 << '\n';
    return 0;
}
실행 결과
3
3.5
3
3.5
  • static_cast<double>(a) — 'a의 값을 double로 바꾼 값'입니다. a 칸 자체는 int 그대로이고, 계산에 쓰이는 값만 7.0이 됩니다.
  • 그래서 static_cast<double>(a) / b는 7.0 / 2와 같은 계산입니다. 한쪽이 double이면 다른 쪽(int 2)도 double로 바뀌어 실수 나눗셈을 하므로 3.5입니다.
  • static_cast<double>(a / b) — 괄호 안의 a / b가 먼저 int로 계산되어 3이 된 뒤에 바꾸므로 3.0입니다. 캐스트의 위치가 틀린 흔한 실수입니다.
  • 변수가 아니라 숫자를 직접 쓸 때는 7.0처럼 소수점을 붙이는 것으로 충분합니다.

C 스타일 캐스트: (int)x

C 언어에서는 (바꿀 타입)값으로 변환합니다. C++에서도 그대로 동작합니다.

#include <iostream>
using namespace std;

int main() {
    int a = 7;
    int b = 2;
    cout << (double)a / b << '\n';
    cout << (int)3.99 << ' ' << (int)-3.99 << '\n';
    return 0;
}
실행 결과
3.5
3 -3

결과는 static_cast와 같습니다. 그런데도 C++에서 static_cast를 권장하는 이유는 두 가지입니다. 코드에서 검색하기 쉽고((int)는 괄호에 묻혀 눈에 잘 안 띕니다), 포인터 타입을 억지로 바꾸는 것 같은 위험한 변환을 막아 주기 때문입니다(9장). 코딩테스트 코드에서는 둘 다 흔히 보이고, C에는 (int)x 형태만 있습니다.

10const와 매직 넘버, constexpr과 auto

값을 한 번 정하면 바꿀 일이 없는 변수가 있습니다. 원주율, 최대 속도, 세율 같은 값입니다. 이런 변수 앞에 const를 붙이면 상수(constant)가 되어 바꿀 수 없게 됩니다.

#include <iostream>
using namespace std;

int main() {
    const double PI = 3.14159;
    double radius = 2.0;
    double area = PI * radius * radius;
    cout << area << '\n';
    return 0;
}
실행 결과
12.5664

3.14159 × 2 × 2 = 12.56636이고, 기본 출력이 유효숫자 6자리이므로 12.5664입니다. const 변수에 값을 대입하려고 하면 컴파일러가 막습니다.

#include <iostream>
using namespace std;

int main() {
    const int MAX_SPEED = 120;
    MAX_SPEED = 150;
    cout << MAX_SPEED << '\n';
    return 0;
}
컴파일 에러
main.cpp:6:15: error: assignment of read-only variable 'MAX_SPEED'
    6 |     MAX_SPEED = 150;
      |     ~~~~~~~~~~^~~~~

read-only variable은 '읽기 전용 변수'라는 뜻입니다. 나중에 값을 넣을 방법이 없으므로 const 변수는 선언할 때 반드시 초기화해야 합니다. const int LIMIT;처럼 쓰면 error: uninitialized 'const LIMIT'이 납니다.

매직 넘버를 이름으로 바꾸기

코드 한가운데 설명 없이 박혀 있는 숫자를 매직 넘버(magic number)라고 합니다. 다음 두 코드는 같은 계산을 합니다.

// 매직 넘버: 0.1과 3000이 무엇인지 코드만 봐서는 알 수 없다
double fee = price * 0.1 + 3000;

// 이름 붙은 상수: 뜻이 드러난다
const double TAX_RATE = 0.1;
const int SHIPPING_FEE = 3000;
double fee = price * TAX_RATE + SHIPPING_FEE;

상수로 바꾸면 좋은 점이 세 가지입니다. 첫째, 읽는 사람이 숫자의 뜻을 압니다. 둘째, 값이 바뀌면 한 곳만 고치면 됩니다. 세율 0.1이 코드 열 군데에 흩어져 있으면 하나쯤 빠뜨리기 쉽습니다. 셋째, 실수로 값을 바꾸는 코드를 컴파일러가 막아 줍니다. 펌웨어의 PWM 주기, 바퀴 지름, 센서 변환 계수도 모두 이렇게 이름을 붙입니다. C 펌웨어에서는 #define WHEEL_DIAMETER_MM 65처럼 매크로를 많이 쓰는데, 매크로는 타입이 없는 단순 글자 치환이라 C++에서는 const를 권장합니다(매크로는 29장). 이 노트는 상수 이름을 대문자와 밑줄로 씁니다. 관례는 팀마다 다릅니다.

constexpr: 컴파일할 때 정해지는 상수

constexpr int MAX_N = 100000;처럼 쓰는 constexpr은 '값이 컴파일할 때 확정되어야 하는 상수'입니다. 6장에서 배울 배열의 크기처럼 컴파일 시점에 값을 알아야 하는 자리에 씁니다. 지금은 'const의 더 엄격한 버전'으로 알아 두면 충분합니다.

auto: 타입을 컴파일러에게 맡기기

auto로 선언하면 컴파일러가 초기값을 보고 타입을 정합니다. 이것을 타입 추론(type inference)이라고 합니다.

#include <iostream>
using namespace std;

int main() {
    auto a = 5;
    auto b = 5.0;
    auto c = 7 / 2;
    auto d = 'x';
    cout << a << ' ' << b << ' ' << c << ' ' << d << '\n';
    cout << sizeof(a) << ' ' << sizeof(b) << ' ';
    cout << sizeof(c) << ' ' << sizeof(d) << '\n';
    return 0;
}
실행 결과
5 5 3 x
4 8 4 1

sizeof는 변수에도 쓸 수 있습니다. a는 int(4바이트), b는 double(8바이트), c는 7 / 2가 int이므로 int이고 값은 3.5가 아니라 3, d는 char(1바이트)입니다. 편해 보이지만 함정이 있습니다.

#include <iostream>
using namespace std;

int main() {
    auto name = "Kim";
    cout << name + " Chulsoo" << '\n';
    return 0;
}
컴파일 에러
main.cpp:6:18: error: invalid operands of types 'const char*' and 'const char [9]' to binary 'operator+'

auto name = "Kim";의 name은 string이 아니라 문자열 리터럴 타입(const char*)이 됩니다. 8절에서 본 '리터럴끼리는 + 불가' 문제가 그대로 나타납니다. string name = "Kim";이라고 타입을 직접 썼다면 아무 문제가 없었습니다.

핵심 정리 처음에는 auto 대신 타입을 직접 쓰세요. 타입을 직접 쓰는 것 자체가 '이 값의 종류와 범위가 무엇인가'를 생각하는 연습입니다. auto는 11장의 반복자처럼 타입 이름이 아주 길고 뻔할 때 쓰면 됩니다.

11입력 cin 자세히: >>와 getline

1장에서 본 cin >>의 규칙을 다시 정리합니다. >>는 값 하나를 읽을 때 앞쪽의 공백(스페이스, 탭, 줄바꿈)을 건너뛰고, 값이 끝나는 곳에서 멈춥니다. 그래서 입력이 한 줄(3 5)이든 두 줄(3⏎5)이든 결과가 같습니다. 여러 타입을 한 번에 읽을 수도 있습니다.

입력
Kim 20 175.5
#include <iostream>
#include <string>
using namespace std;

int main() {
    string name;
    int age = 0;
    double height = 0.0;
    cin >> name >> age >> height;
    cout << name << '/' << age << '/' << height << '\n';
    return 0;
}
실행 결과
Kim/20/175.5

>>가 '값이 끝나는 곳'을 정하는 기준은 변수의 타입입니다.

double숫자와 소수점(.)이 이어지는 데까지
string공백이 아닌 글자가 이어지는 데까지 (한 단어)
char공백이 아닌 글자 딱 하나

#include <iostream>

getline: 공백까지 한 줄 통째로

1장에서 cin >> str에 Hello World를 넣으면 Hello까지만 읽혔습니다. 공백을 포함한 한 줄 전체를 읽으려면 getline(cin, 변수)를 씁니다.

입력
Hello World
#include <iostream>
#include <string>
using namespace std;

int main() {
    string line;
    getline(cin, line);
    cout << "[" << line << "]" << '\n';
    return 0;
}
실행 결과
[Hello World]

getline(cin, line)은 지금 위치부터 줄바꿈 문자 직전까지를 공백까지 전부 읽어 string 변수 line에 넣고, 줄바꿈 문자는 읽어서 버립니다. >>와 달리 앞쪽 공백도 건너뛰지 않고 그대로 담습니다. 읽어 넣을 변수는 string이어야 합니다.

C++ 쪽은 한 문장이 길어서 두 줄로 나눴습니다. ;가 나올 때까지가 한 문장이므로 이렇게 나눠 써도 됩니다.

  • printf("%d x %d = %d\n", w, h, w * h); — 괄호 안에 쉼표로 나눠 넘기는 값 하나하나를 인자(argument)라고 합니다. 첫 번째 인자는 서식 문자열(format string)입니다. 그 안의 %d 자리에 뒤에 오는 값들이 순서대로 들어갑니다. 첫 %d에 w, 둘째에 h, 셋째에 w * h. %d는 'int를 10진수로 출력'이라는 서식 지정자(format specifier)입니다. 줄바꿈 \n은 직접 넣어야 합니다.
  • scanf("%d %d", &w, &h); — 입력에서 서식대로 정수 두 개를 읽어 w와 h에 넣습니다. 변수 이름 앞의 &는 '변수의 위치(주소)를 알려 준다'는 뜻입니다. printf는 값만 알면 출력할 수 있지만, scanf는 읽은 값을 어느 칸에 써 넣을지 알아야 하므로 칸의 위치를 받습니다. &와 주소의 정체는 9장(포인터)에서 배웁니다.

지금까지 본 입출력형 문제는 main을 직접 쓰고, cin으로 읽고, cout으로 출력했습니다. 프로그래머스 문제의 대부분은 함수형입니다. 언어를 C++로 고르면 이런 초기 코드가 보입니다(15절 '두 수의 합'의 예).

#include <string>
#include <vector>

using namespace std;

int solution(int num1, int num2) {
    int answer = 0;
    return answer;
}
부분뜻
#include <string>
#include <vector>		템플릿에 기본으로 들어 있는 헤더입니다. 이 문제에서는 쓰지 않지만 그대로 둬도 됩니다. vector는 6장에서 배웁니다.
맨 앞의 int반환형(return type): 돌려줄 답의 타입입니다. 답이 클 수 있는 문제는 여기가 long long입니다.
solution함수(function)의 이름입니다. 채점기가 이 이름으로 부르므로 바꾸면 안 됩니다.
(int num1, int num2)매개변수(parameter): 채점기가 넣어 주는 입력값입니다. 함수가 시작될 때 이미 값이 들어 있습니다.
int answer = 0;답을 담으라고 만들어 둔 변수입니다. 편의를 위한 것일 뿐 꼭 써야 하는 것은 아닙니다.
return answer;answer의 값을 채점기에 돌려줍니다. 이 값이 채점 대상입니다.

함수는 '값을 받아 일을 하고 결과를 돌려주는 코드 묶음'이고, 정식으로는 8장에서 배웁니다. 지금은 템플릿 모양을 그대로 두고 빈 곳만 채운다고 생각하세요.

main이 없는 이유

main은 채점기(grader)가 갖고 있습니다. 채점기의 main이 테스트 케이스마다 solution을 호출(call)하고, 돌려받은 값을 정답과 비교합니다. 그 과정을 흉내 내 보겠습니다. 예로 쓴 solution은 직사각형의 가로와 세로를 받아 둘레를 돌려줍니다.

#include <iostream>
using namespace std;

int solution(int width, int height) {
    int answer = 2 * (width + height);
    return answer;
}

// 아래 main은 채점기가 하는 일을 흉내 낸 것입니다.
// 프로그래머스에 제출할 때는 main을 쓰지 않습니다.
int main() {
    cout << solution(3, 4) << '\n';
    cout << solution(10, 1) << '\n';
    return 0;
}
실행 결과
14
22
  1. main이 solution(3, 4)를 호출합니다. 괄호 안의 값이 순서대로 매개변수에 들어가서, width = 3, height = 4인 상태로 solution이 실행을 시작합니다.
  2. solution이 2 × (3 + 4) = 14를 계산해 answer에 담고, return answer;로 14를 돌려줍니다.
  3. main은 돌려받은 14를 사용합니다. 여기서는 출력했지만, 채점기는 이 값을 테스트 케이스의 정답과 비교해 통과/실패를 표시합니다. 다음 테스트 케이스 (10, 1)로 같은 일을 반복합니다.

정리하면 괄호 안 = 채점기가 넣어 주는 값, return = 내가 돌려주는 답입니다. 위처럼 main을 붙여 예제 값으로 호출해 보는 방법은 내 컴퓨터에서 solution을 시험할 때도 그대로 씁니다.

함수형 문제의 흔한 실수 네 가지
  • 매개변수를 cin으로 다시 읽기. 입력은 매개변수로 이미 들어와 있고, 함수형 문제에는 cin으로 읽을 입력이 주어지지 않습니다.
  • 답을 cout으로 출력만 하고 return하지 않기. 채점은 return 값으로만 합니다. answer가 0 그대로면 실패입니다.
  • main을 넣은 채로 제출하기. 채점기의 main과 겹쳐서 에러가 납니다. main은 내 컴퓨터에서 시험할 때만 붙이세요.
  • 함수 이름, 매개변수, 반환형 바꾸기. 채점기가 정해진 모양의 solution을 찾지 못해 에러가 납니다.

'코드 실행'과 '제출 후 채점', 그리고 cout 디버깅

  • 코드 실행: 문제에 나온 입출력 예(와 내가 추가한 테스트 케이스)로만 돌려 보고, 케이스마다 기댓값과 내 return 값을 보여 줍니다.
  • 제출 후 채점: 화면에 보이지 않는 여러 테스트 케이스로 return 값을 채점합니다. 예제를 통과해도 여기서 틀릴 수 있습니다. 오버플로(5절)나 정수 나눗셈(9절)이 대표적인 원인입니다.

solution 안에서 중간값을 cout으로 출력하면 '코드 실행' 결과 화면에 함께 표시되어 디버깅에 쓸 수 있습니다. 템플릿에는 <iostream>이 없으므로 직접 추가해야 합니다.

#include <iostream>
#include <string>
#include <vector>

    int answer = 2 * (width + height);
    // 디버깅용 출력: 제출 전에 지우기

         << " answer=" << answer << '\n';

채점에는 return 값만 쓰이므로 출력이 정답에 영향을 주지는 않지만, 출력이 많으면 느려질 수 있습니다. 디버깅용 출력은 제출 전에 지우는 습관을 들이세요.

빈칸 채우기와 입출력형

변수 몇 개에 값을 저장해 두고 출력하는 초기 코드의 빈칸을 채워서, 정해진 문장 한 줄과 13, 310을 차례로 출력하게 만드는 문제입니다.

연습 포인트: 같은 +가 int에서는 덧셈(3 + 10 = 13), string에서는 이어 붙이기("3" + "10" = "310")가 된다는 8절의 핵심. 변수의 타입이 연산의 뜻을 정합니다.

힌트 1

힌트 2

13은 int 3 + 10, 310은 string "3" + "10"입니다. 빈칸이 변수의 값 자리라면 따옴표가 있느냐 없느냐가 핵심입니다. 3은 정수, "3"은 문자열입니다. 첫 줄의 문장은 출력 예시와 글자 하나, 공백 하나까지 똑같아야 합니다.

풀이 코드와 해설

#include <string>

    cout << val1 + 10 << '\n';
    cout << val2 + "10" << '\n';
    return 0;
}

13

초기 코드에 대해: PCCE 문제는 화면에 빈칸이 있는 초기 코드가 주어지는데, 이 노트에서는 그 코드를 그대로 볼 수 없습니다. 같은 문제의 다른 언어 풀이를 보면 구조는 위와 같습니다. 문장을 담은 변수, 정수 3을 담은 변수, 문자열 "3"을 담은 변수를 만들고 각각 그대로, + 10, + "10" 해서 출력합니다. 화면의 초기 코드에서 빈칸만 채우고 나머지 줄은 그대로 두세요. 초기 코드가 '\n' 대신 endl을 써도 결과는 같습니다.

빈칸이 있을 만한 곳: 변수에 넣는 값(3과 "3")이나 변수의 타입(int와 string)일 가능성이 큽니다. 출력 줄은 이미 val1 + 10, val2 + "10"으로 쓰여 있으니, 그 줄이 13과 310을 내도록 변수 쪽을 맞추는 것이 이 문제의 핵심입니다.

  • val1 + 10: val1이 int 3이므로 덧셈 13입니다.
  • val2 + "10": val2가 string "3"이므로 이어 붙이기 "310"입니다.

흔한 실수: val2를 int val2 = 3;으로 만들면 val2 + "10"이 8절의 '숫자 + 문자열 리터럴' 함정이 되어 에러도 없이 엉뚱하게 동작합니다. 반대로 val1을 string으로 만들면 val1 + 10이 string + int라서 컴파일 에러가 납니다. 첫 줄은 대소문자와 공백까지 Spring is beginning과 정확히 같아야 합니다.
