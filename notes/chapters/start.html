이 챕터를 마치면:
  • 이 노트의 전체 순서(Part A → B → C)와 챕터마다의 목표 수준을 압니다.
  • 프로그래머스에서 C++로 문제를 열고 코드 실행, 제출 후 채점하기, 테스트 케이스 추가하기를 구별해 씁니다.
  • 함수형 문제와 입출력형 문제를 구별하고, 각각 답을 어떻게 내는지(return / cout) 압니다.
  • 문제를 푸는 7단계 루틴, 막혔을 때의 규칙, AI(Claude)에게 질문하는 방법을 정해 둡니다.

1이 챕터에서 배울 것과 이유

이 챕터에는 문법이 나오지 않습니다. 대신 앞으로 31개 챕터를 어떤 순서로, 어떤 방법으로 공부할지 정합니다. 같은 노트를 읽어도 고개만 끄덕이며 읽는 공부와, 직접 쓰고 틀려 보는 공부는 몇 달 뒤 결과가 완전히 다릅니다.

  • 코딩테스트: 시간 제한이 있고 AI 없이 혼자 봅니다. 혼자 써 본 양만큼만 실력이 됩니다. 그래서 문제를 푸는 순서(루틴)와 막혔을 때의 규칙을 첫날부터 정해 둡니다.
  • 임베디드 현업: 모터가 갑자기 멈추거나 CAN 통신이 끊기면, 원인은 데이터시트와 디버거 앞에서 직접 찾아야 합니다. 이해하지 못한 채 붙여 넣은 코드는 바로 이런 순간에 고칠 수 없습니다.

먼저 복습할 챕터는 없습니다. 준비물은 이 노트와 프로그래머스 계정뿐입니다.

2이 노트의 목표와 전체 지도

출발점은 "코드를 한 줄도 혼자 못 쓴다"입니다. 변수(variable)가 무엇인지도 2장에서 처음부터 설명합니다. AI로 프로젝트를 만들어 봤다면, 코드를 읽으면 대충 아는 것과 빈 화면에서 직접 쓰는 것이 전혀 다르다는 것을 이미 느꼈을 겁니다. 이 노트는 두 번째 능력을 기릅니다.

도착점은 두 가지입니다.

  1. 코딩테스트: 프로그래머스 Lv.3 문제를 C++로 혼자 푸는 실력. 기업 코딩테스트를 통과할 기본기입니다.
  2. 임베디드 기본기: 포인터와 메모리 구조, 비트 연산, volatile, 구조체 패딩, 링 버퍼(ring buffer), 상태 머신, PID 제어 코드의 뼈대처럼 로봇·차량 제어 코드를 읽고 쓰는 데 필요한 C/C++.

전체 지도는 다음과 같고, 순서대로 갑니다.

  1. Part 0 시작(0장, 이 챕터) — 공부 방법, 프로그래머스 사용법, AI 사용 규칙.
  2. Part A 언어 기초(1–12장) — 출력, 변수, 연산자, 조건문, 반복문, 배열, 문자열, 함수, 포인터, 구조체, STL, 시간 복잡도. 끝나면 Lv.0 대부분과 Lv.1, Lv.2 입문 문제를 풉니다.
  3. Part B 알고리즘(13–28장) — 구현, 정렬, 해시, 스택·큐, 힙, 완전탐색, 그래프 탐색, 이분 탐색, 그리디, DP, 최단 경로. 목표는 Lv.2 대부분과 Lv.3 문제를 혼자 푸는 것입니다.
  4. Part C 임베디드 C/C++(29–31장) — C와 C++의 차이, 비트 연산, 메모리 맵, volatile, 인터럽트, 링 버퍼, 상태 머신, PID, CAN 파싱, ROS 2 쪽 모던 C++.
  5. 부록 A·B·C — C++ 치트시트, 에러 메시지와 채점 결과 사전, 전체 문제 목록.
핵심 정리 챕터는 앞에서부터 차례로 쌓입니다. N장의 예제는 N장까지 배운 문법만 씁니다. 아직 안 배운 문법이 꼭 필요할 때는 "지금은 이 줄을 그대로 두세요. ○장에서 설명합니다"라고 적어 두니, 그 줄은 모양만 따라 쓰면 됩니다. 그래서 앞 챕터를 건너뛰지 않는 것이 가장 빠른 길입니다.

6왜 C++로 코딩테스트를 보고, 왜 C도 따로 배우나

코딩테스트는 C++로 준비합니다. 이유는 두 가지입니다.

  • STL 덕분에 짧고 빠르게 풉니다. C++에는 표준 라이브러리(standard library), 특히 STL(Standard Template Library)이 들어 있어서 정렬, 크기가 늘어나는 배열(vector), 해시 테이블(unordered_map), 우선순위 큐(priority_queue) 같은 도구를 바로 씁니다. C로 풀면 이런 도구를 직접 만들어야 해서 시험 시간의 상당 부분이 도구 만드는 데 들어갑니다.
  • 실행 속도가 빠릅니다. C++는 기계어로 컴파일(compile)되는 언어라 같은 방법으로 풀어도 대체로 빨리 돌고, 시간 제한에 여유가 있습니다.

Python도 코딩테스트에 많이 쓰이지만, 임베디드 진로라면 C++로 연습하는 쪽이 이득입니다. 코딩테스트 준비가 그대로 현업 언어 연습이 되기 때문입니다.

C와 C++의 관계. C++는 C에서 출발한 언어입니다. 변수, 연산자, 조건문, 반복문, 함수, 배열, 포인터 같은 기본 문법은 거의 같고, C++는 여기에 클래스, 템플릿, STL 같은 기능을 더했습니다. 정확히는 C++가 C를 100% 포함하지는 않아서 C에서만 되는 문법도 조금 있지만, 지금은 "기본 문법을 공유한다"로 충분합니다. 그래서 이 노트는 다음 순서로 갑니다.

  1. C++ 기초(1–12장): C와 공통인 문법을 C++로 배웁니다. 1–9장에서는 "C에서는 어떻게 쓰는지"를 함께 표시하고, 9장에서는 몇 문제를 C로도 풀어 봅니다.
  2. 알고리즘(13–28장): C++ STL을 무기로 코딩테스트 실력을 만듭니다. 정렬, 스택, 큐 같은 것은 원리를 이해하도록 직접 구현도 해 봅니다.
  3. 임베디드 C 심화(29–31장): 펌웨어에서 쓰는 C의 깊은 부분(고정 폭 정수, 비트 연산, volatile, 메모리 맵)과 제어 코드를 다룹니다.

임베디드 진로에서 언어는 대략 이렇게 나뉩니다. 회사와 제품마다 다르지만 흔한 경우입니다.

함수형: solution 함수만 완성한다

프로그래머스 문제 대부분이 이 형식입니다. 예를 들어 2장의 첫 함수형 문제 두 수의 합에서 C++를 고르면 이런 초기 코드가 나옵니다.

#include <string>
#include <vector>

using namespace std;

int solution(int num1, int num2) {
    int answer = 0;
    return answer;
}
  • solution: 내가 완성할 함수(function)입니다. 이름 뒤 괄호 속 내용은 문제마다 다릅니다.
  • int num1, int num2: 매개변수(parameter). 채점기가 넣어 주는 입력입니다. 입력을 직접 읽을 필요가 없습니다.
  • return answer;: 반환(return). return 뒤의 값이 내 답으로 채점됩니다.
  • main이 없습니다. 프로그램의 시작점인 main은 채점기가 가지고 있습니다.

채점기는 대략 이렇게 움직입니다(이 문제의 입출력 예 기준).

2num1이 2, num2가 3인 상태로 중괄호 안을 실행합니다

함수 문법 자체는 8장에서 배웁니다. 그 전인 2장부터 함수형 문제를 풀 수 있도록, 이 템플릿은 모양 그대로 두고 중괄호 { } 안만 채우는 법을 그때그때 알려 드립니다.

입출력형: main을 직접 쓰고 cin으로 읽고 cout으로 출력한다

코딩 기초 트레이닝의 일부 문제와 일부 PCCE 기출이 이 형식입니다. 예를 들어 단어 하나를 입력받는 문제라면 초기 코드가 이런 모양입니다. 문제마다 조금씩 다르고, // 뒤의 설명은 이해를 돕기 위해 붙인 메모(주석)입니다.

#include <iostream>
#include <string>

using namespace std;

int main(void) {
    string str;
    cin >> str;
    // 여기에 답을 출력하는 코드를 씁니다
    return 0;
}
  • main: 프로그램의 시작점입니다. 입출력형에서는 프로그램 전체가 내 몫입니다(뼈대는 대개 초기 코드에 있습니다).
  • cin >> str;: 입력을 읽습니다. 채점기는 입력 데이터를 표준 입력(standard input, 원래 키보드가 연결되는 자리)으로 넣어 줍니다.
  • 답은 cout으로 표준 출력(standard output, 원래 화면 자리)에 씁니다. 채점기는 출력된 글자 전체를 기댓값과 비교합니다.

입출력형은 백준(BOJ)이나 삼성 SW 역량테스트 같은 곳에서는 기본 형식이니 익숙해져야 합니다. cout은 1장, cin은 1–2장에서 배웁니다.

9문제 푸는 7단계 루틴

모든 문제를 같은 순서로 풉니다. 처음엔 번거롭게 느껴져도, 순서가 몸에 붙으면 처음 보는 문제 앞에서 막막함이 줄어듭니다.

  1. 문제를 끝까지 읽고 밑줄 긋기. 입력(무엇이 주어지나), 출력(무엇을 돌려주거나 출력하나), 제한사항(값의 범위, 길이)을 종이나 메모장에 세 줄로 옮겨 적습니다.
  2. 입출력 예를 손으로 따라가기. 예제 하나를 코드 없이 종이에서 직접 계산해 기댓값이 나오는지 확인합니다. 여기서 답이 안 나오면 문제를 잘못 이해한 것이니 '입출력 예 설명'을 다시 읽습니다.
  3. 제한사항으로 방법 정하기. 입력이 클수록 빠른 방법이 필요합니다. 입력 크기를 보고 어떤 방법이 시간 안에 도는지 판단하는 법은 12장에서 배웁니다. 그 전에는 "입력이 최대 얼마인지"만 적어 둡니다.
  4. 한국어로 의사코드 쓰기. 의사코드(pseudocode)는 프로그래밍 언어 대신 우리말로 쓴 풀이 순서입니다. 아래 예처럼 몇 줄이면 충분합니다.
  5. 코드 작성. 의사코드 한 줄을 코드 몇 줄로 옮깁니다. 복사·붙여넣기와 AI 자동완성 없이 직접 칩니다.
  6. 예제와 내가 만든 엣지 케이스로 코드 실행. 엣지 케이스(edge case)는 제한사항의 끝에 있는 특이한 입력입니다. 가장 작은 값, 가장 큰 값, 길이 1, 모두 같은 값, 0이나 음수 같은 것을 테스트 케이스 추가하기로 넣어 봅니다.
  7. 제출하고, 틀리면 디버깅. 디버깅(debugging)은 틀린 원인을 찾아 고치는 일입니다. 2단계의 손 계산과 코드의 중간 값을 비교하세요. 함수형 문제에서도 cout으로 찍은 값은 코드 실행 결과 창에 보이므로, 어느 줄에서 손 계산과 달라지는지 찾을 수 있습니다.

4단계 의사코드의 예입니다. '정수 배열에서 짝수가 몇 개인지 돌려주기' 같은 문제라면 이렇게 씁니다.

개수를 0으로 둔다
배열의 수를 하나씩 꺼내서:
    그 수를 2로 나눈 나머지가 0이면(짝수면) 개수를 1 늘린다
개수를 돌려준다(return)

이 네 줄을 C++로 옮기는 데 필요한 나머지 연산, 반복문, 배열은 3장, 5장, 6장에서 배웁니다.

정답을 맞힌 뒤에

  • 다른 사람의 풀이 2–3개를 읽고 내 풀이와 비교합니다. 더 짧은 방법, 처음 보는 함수, 더 빠른 방법을 하나라도 찾아 메모합니다.
  • 3일 뒤 빈 화면에서 다시 풉니다. 내 코드를 따로 저장해 둔 다음 초기화를 누르고 처음부터 씁니다. 막힘없이 써지면 그 문제는 내 것입니다.

10AI와 공부하는 규칙: 바이브코딩 탈출

AI가 짜 준 코드를 읽으면 '대충 알 것 같은' 상태가 됩니다. 하지만 코딩테스트, 기술면접, 현장 디버깅에서 필요한 것은 빈 화면에서 직접 쓰는 능력이고, 이 능력은 직접 써 본 양으로만 늘어납니다. 그래서 다음 규칙을 정합니다. 이 노트로 공부하다가 궁금한 점이 생기면 언제든 Claude에게 가져오세요. 다만 이 규칙대로 물어보세요.

  1. 문제를 풀 때는 AI 자동완성과 코드 생성을 끕니다. 내 컴퓨터의 편집기에 Copilot 같은 AI 기능이 있다면 공부할 때는 꺼 둡니다.
  2. Claude는 선생님으로만 씁니다. 쓰임은 네 가지입니다. (a) 개념 질문: 예제와 함께 설명을 듣기 (b) 내 코드 리뷰: 정답 코드가 아니라 틀린 이유를 힌트로 받기 (c) 반례(counterexample, 내 코드가 틀리는 입력) 요청 (d) 정답을 맞힌 뒤 더 나은 방법과 비교.
  3. 받은 설명은 직접 실행해서 확인합니다. AI의 설명도 틀릴 수 있습니다. 작은 코드를 써서 돌려 보는 것이 가장 확실한 확인입니다.
