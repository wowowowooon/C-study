연산자: 계산하고 비교하기Operators

이 챕터를 마치면: ① 7 / 2, -7 % 2, 7 / 2.0처럼 정수·실수·음수가 섞인 계산의 결과를 실행하기 전에 정확히 예측할 수 있습니다. ② 몫과 나머지로 자릿수 떼기, 시간 변환, 올림 나눗셈, 순환(시계·각도)을 식 한 줄로 쓸 수 있습니다. ③ 비교·논리·비트 연산자와 우선순위를 알고 x & 1 == 0, 2 ^ 3, 1000000 * 1000000 같은 함정을 스스로 찾아낼 수 있습니다. ④ 연산자만으로 풀리는 프로그래머스 Lv.0 문제 10개를 직접 풀 수 있습니다.

1이 챕터에서 배울 것과 이유

코딩테스트: Lv.0 문제의 상당수는 몫, 나머지, 비교만으로 풀립니다. 자릿수 떼기, 짝수·홀수, 배수, 시간 변환, 올림 계산이 모두 이 챕터의 연산자입니다. Lv.2~3에서도 정수 나눗셈, 오버플로, 연산자 우선순위 실수는 '예제는 맞는데 제출하면 틀리는' 가장 흔한 원인입니다. 이런 실수는 에러 메시지 없이 조용히 틀린 값을 내기 때문에 규칙을 정확히 알아야만 잡을 수 있습니다.

임베디드: ADC 값을 전압으로 바꾸는 계산, UART 링 버퍼의 인덱스 되감기, GPIO 레지스터의 비트 켜기·끄기가 모두 이 챕터의 연산자로 이루어집니다. FPU(실수 연산 장치)가 없는 MCU에서는 정수 연산을 어떤 순서로 하느냐가 곧 정밀도이고, 나눗셈 명령이 없는 MCU에서는 / 하나에 수십 사이클이 듭니다.

준비: 2장의 int, long long, double, bool, 형 변환(static_cast, (int)), INT_MAX와 오버플로를 기억하면 충분합니다. 이 챕터에는 아직 if와 반복문이 없습니다. 모든 예제는 위에서 아래로 한 줄씩, 한 번만 실행됩니다.

먼저 용어 세 개를 정리합니다. a + b에서 +처럼 계산을 지시하는 기호를 연산자(operator), a와 b처럼 연산자가 다루는 값을 피연산자(operand)라고 합니다. a + b * 2처럼 계산하면 값 하나가 나오는 코드 조각은 식(expression)입니다. 피연산자가 두 개인 연산자를 이항(binary) 연산자, -x나 !x처럼 하나인 연산자를 단항(unary) 연산자라고 합니다. 컴파일 에러 메시지에 이 단어들이 영어로 그대로 나오므로 지금 익혀 두세요.

2산술 연산자: + - * / %

사칙연산과 나머지입니다. 먼저 실행해 보고 결과를 하나씩 확인합니다.

#include <iostream>
using namespace std;

int main() {
    int a = 7;
    int b = 2;
    cout << a + b << '\n';
    cout << a - b << '\n';
    cout << a * b << '\n';
    cout << a / b << '\n';
    cout << a % b << '\n';
    return 0;
}

  • a + b, a - b, a * b: 수학과 같습니다. 곱셈 기호는 ×가 아니라 *입니다.
  • a / b가 3.5가 아니라 3입니다. int끼리 나누면 결과도 int이고, 소수점 아래는 반올림 없이 버립니다. 즉 정수 나눗셈은 몫을 구합니다.
  • a % b는 나머지(remainder)입니다. 7 = 2 × 3 + 1이므로 1입니다. 퍼센트가 아니라 '나머지 연산자(modulo)'라고 읽습니다.

몫과 나머지 사이에는 항상 다음 관계가 성립합니다. 이 관계를 기억하면 음수의 경우도 스스로 계산할 수 있습니다.

핵심 정리

(a / b) * b + a % b == a — b가 0이 아니면 항상 성립합니다.
7을 2로 나누면 몫 3, 나머지 1 → 3 × 2 + 1 = 7

두 수 중 하나라도 실수(double)면 결과도 실수가 되어 소수점 아래가 남습니다.

#include <iostream>
using namespace std;

int main() {
    cout << 7 / 2 << '\n';
    cout << 7.0 / 2 << '\n';
    cout << 7 / 2.0 << '\n';
    cout << 7.0 / 2.0 << '\n';
    return 0;
}
실행 결과
3
3.5
3.5
3.5

7은 정수 리터럴(int), 7.0은 실수 리터럴(double)입니다. 소수점 하나가 계산 방식을 바꿉니다. 타입이 섞였을 때의 정확한 규칙은 12절에서 정리합니다.

음수의 몫과 나머지

수학에서는 −7을 2로 나누면 몫 −4, 나머지 1이라고 배웠을 수 있습니다. C++은 다릅니다.

#include <iostream>
using namespace std;

int main() {
    cout << -7 / 2 << ' ' << -7 % 2 << '\n';
    cout << 7 / -2 << ' ' << 7 % -2 << '\n';
    cout << -7 / -2 << ' ' << -7 % -2 << '\n';
    return 0;
}
실행 결과
-3 -1
-3 1
3 -1

C++11부터 표준이 정한 규칙은 두 가지입니다.

  1. 몫은 0 쪽으로 버립니다(truncation toward zero). −3.5는 −4가 아니라 −3이 됩니다. 계산한 뒤 소수점 아래를 그냥 지운다고 생각하면 됩니다. C++11 이전에는 이 방향을 컴파일러가 정해도 됐지만, 지금은 표준이 보장합니다.
  2. 나머지는 핵심 정리의 식이 맞도록 정해집니다. −7 = 2 × (−3) + (−1)이므로 나머지는 −1입니다. 결과적으로 나머지의 부호는 나뉘는 수(왼쪽 피연산자)를 따릅니다. 그래서 7 % -2는 1, -7 % 2는 −1입니다.
음수 나머지: -7 % 2는 1이 아니라 −1입니다. 그래서 '홀수인가?'를 n % 2 == 1로 검사하면 n이 음수 홀수일 때 틀립니다. 홀수 검사는 n % 2 != 0으로 쓰는 습관을 들이세요(==, !=는 6절). 파이썬은 -7 % 2가 1이라서, 파이썬 풀이를 C++로 옮길 때 이 차이로 자주 틀립니다.

0으로 나누기

정수를 0으로 나누면 어떻게 될까요? 컴파일러가 미리 알 수 없도록 나누는 수를 입력으로 받아 봅니다. 입력은 0입니다.

#include <iostream>
using namespace std;

int main() {
    int a = 10;
    int b = 1;
    cin >> b;
    cout << "나누기 전" << '\n';
    cout << a / b << '\n';
    cout << "나눈 후" << '\n';
    return 0;
}
터미널에 나온 것 (보장되지 않음)
나누기 전
Floating point exception
  • 정수를 0으로 나누는 것은 정의되지 않은 동작(undefined behavior)입니다. 2장의 오버플로처럼 표준이 결과를 정하지 않았으므로 무슨 일이든 일어날 수 있습니다. 그래서 이 블록의 결과는 보장되지 않습니다.
  • 64비트 리눅스(x86-64)에서는 CPU가 나눗셈 예외를 일으키고, 운영체제가 프로그램을 강제로 끝냅니다(SIGFPE라는 신호). "나눈 후"는 끝내 출력되지 않습니다. 메시지에 Floating point(부동소수점)라고 나오지만 원인은 정수 나눗셈입니다. 이름이 역사적으로 그렇게 붙었을 뿐입니다. 환경에 따라 뒤에 (core dumped)가 붙기도 합니다.
  • 프로그래머스에서는 이런 비정상 종료가 런타임 에러로 채점됩니다.
  • 코드에 10 / 0처럼 0을 직접 쓰면 g++가 warning: division by zero [-Wdiv-by-zero] 경고를 띄웁니다. 하지만 위처럼 입력이나 계산 결과가 0이 되는 경우는 컴파일러가 잡지 못합니다.
  • 같은 코드를 STM32F4 같은 Cortex-M3/M4 MCU에서 돌리면, 기본 설정에서는 나눗셈 명령이 몫 0을 내놓고 프로그램이 그냥 계속 달립니다(CCR 레지스터의 DIV_0_TRP 비트를 켜면 예외가 발생). PC에서는 죽고 MCU에서는 조용히 틀린 값으로 달리는 것, 이것이 '정의되지 않은 동작'이 무서운 이유입니다.

실수는 다르게 동작합니다.

#include <iostream>
using namespace std;

int main() {
    double x = 1.0;
    double zero = 0.0;
    cout << x / zero << '\n';
    cout << -x / zero << '\n';
    return 0;
}
실행 결과
inf
-inf

inf는 무한대(infinity)입니다. 0.0 / 0.0은 nan(Not a Number, '숫자가 아님')이 되고, 환경에 따라 nan 또는 -nan으로 출력됩니다. 엄밀히 말하면 이 결과는 C++ 표준이 보장하는 것이 아니라, g++를 비롯한 거의 모든 환경이 따르는 IEEE 754 부동소수점 규격이 정한 것입니다. 프로그램은 죽지 않지만, inf나 nan이 한 번 생기면 그 뒤의 계산이 전부 오염되므로 반가운 결과는 아닙니다.

정수 0으로 나누기: 컴파일러는 대부분 잡아 주지 않고, 실행하면 프로그램이 죽거나(PC) 엉뚱한 값이 나옵니다(MCU). 나누는 수가 0이 될 수 있는지 문제의 제한사항에서 먼저 확인하세요. 예를 들어 120805 몫 구하기는 제한사항이 0 < num2라서 안전합니다. 0이 될 수 있다면 7절의 단축 평가나 4장의 if로 먼저 걸러야 합니다. a % 0도 똑같이 정의되지 않은 동작입니다.

3몫과 나머지의 쓰임새 모음

코딩테스트 기초 문제의 절반은 /와 %를 어디에 쓰느냐의 문제입니다. 자주 나오는 패턴을 한 표에 모았습니다. 하나씩 예제로 확인합니다.

짝수·홀수와 배수

using namespace std;

int main() {

    cout << (n % 2 == 0) << '\n';

    return 0;
}

2로 나눈 나머지가 0이면 짝수, 아니면 홀수입니다. k로 나눈 나머지가 0이면 'k로 나누어떨어진다', 즉 k의 배수입니다. ==는 '같은가?'를 묻는 비교 연산자이고, 맞으면 1, 틀리면 0이 출력됩니다. 6절에서 자세히 다룹니다. 4장에서는 이 식을 if의 조건으로 쓰게 됩니다.

자릿수 떼기

#include <iostream>
using namespace std;

int main() {
    int n = 1234;
    cout << n % 10 << '\n';        // 일의 자리
    cout << n / 10 % 10 << '\n';   // 십의 자리
    cout << n / 100 % 10 << '\n';  // 백의 자리
    cout << n / 1000 << '\n';      // 천의 자리
    cout << n / 10 << '\n';        // 일의 자리를 뗀 수
    return 0;
}

3
2
1
123

10진수에서 10으로 나누면 숫자 전체가 오른쪽으로 한 칸 밀립니다. 그래서 n % 10은 밀려 나가는 마지막 자리, n / 10은 남는 부분입니다. n / 10 % 10은 왼쪽부터 차례로 계산합니다. 1234 / 10 = 123, 123 % 10 = 3입니다(같은 우선순위끼리는 왼쪽부터 계산한다는 규칙은 8절). 모든 자릿수를 차례로 떼는 일은 5장에서 반복문으로 n % 10과 n /= 10을 되풀이해서 합니다.

시간 변환

#include <iostream>
using namespace std;

int main() {
    int total = 3725;  // 초
    int h = total / 3600;
    int m = total % 3600 / 60;
    int s = total % 60;
    cout << h << "시간 " << m << "분 " << s << "초" << '\n';
    return 0;
}

초는 왜 total % 3600 % 60이 아니라 total % 60만으로 될까요? 3600은 60의 배수라서, 전체를 60초씩 묶고 남는 것이나 시간을 먼저 빼고 60초씩 묶고 남는 것이나 같기 때문입니다. 큰 단위부터 몫을 구하고 나머지를 다음 단위로 넘기는 이 구조는 거스름돈 계산(120819 아이스 아메리카노)이나 개미 군단(120837)에서 그대로 다시 나옵니다.

올림 나눗셈

}

돌고 도는 값: 시계, 요일, 각도

x % m은 x가 0 이상이면 항상 0부터 m − 1 사이입니다. 그래서 끝에 도달하면 처음으로 돌아가는 값(시계의 시, 요일, 각도, 링 버퍼 인덱스)을 다룰 때 씁니다.

4대입과 복합 대입

2장에서 배운 대로 =는 '같다'가 아니라 '오른쪽 값을 계산해서 왼쪽 변수에 넣는다'입니다. x = x + 3처럼 변수 자신을 바꾸는 일이 워낙 많아서, 줄여 쓰는 복합 대입 연산자(compound assignment)가 있습니다.

#include <iostream>
using namespace std;

int main() {
    int x = 10;
    x += 3;   // x = x + 3
    cout << x << '\n';
    x -= 5;   // x = x - 5
    cout << x << '\n';
    x *= 2;   // x = x * 2
    cout << x << '\n';
    x /= 3;   // x = x / 3 (정수 나눗셈)
    cout << x << '\n';
    x %= 3;   // x = x % 3
    cout << x << '\n';
    return 0;
}

x /= 3도 x와 3이 모두 int이므로 정수 나눗셈입니다. x가 double이었다면 5.33333이 됩니다. 그리고 복합 대입은 변수의 타입을 바꾸지 않습니다. 계산 결과는 언제나 원래 변수의 타입으로 바뀌어 담기므로 int 변수는 계속 int입니다.

=+는 복합 대입이 아닙니다: x += 3;을 x =+ 3;으로 잘못 치면 x = +3;(양수 3을 대입)으로 해석됩니다. x가 10이었다면 13이 아니라 3이 됩니다. 문법상 올바른 코드라서 -Wall -Wextra로도 경고가 나오지 않습니다. 연산 기호가 먼저, =가 나중입니다.

대입식도 값을 가진다

C++에서 대입은 그 자체로 하나의 식이고, 값을 가집니다. 대입식의 값은 '대입된 뒤의 왼쪽 변수'입니다.

    int q = 0;
    int r = 0;

5증감 연산자 ++, --

변수에 1을 더하거나 빼는 일은 반복문(5장)에서 수없이 나옵니다. 그래서 전용 연산자가 있습니다. ++는 1 증가(increment), --는 1 감소(decrement)입니다. 변수 앞에 붙이면 전위(prefix), 뒤에 붙이면 후위(postfix)라고 합니다.

쓰는 법이름변수 a의 변화식 전체의 값
++a전위 증가1 증가증가한 뒤의 값
a++후위 증가1 증가증가하기 전의 값
--a전위 감소1 감소감소한 뒤의 값
a--후위 감소1 감소감소하기 전의 값

혼자 한 문장으로 쓰면 전위와 후위는 완전히 같습니다. count++;와 ++count;는 둘 다 count를 1 늘릴 뿐입니다. 차이는 그 식의 값을 다른 곳에서 쓸 때만 나타납니다.

#include <iostream>
using namespace std;

int main() {
    int a = 5;
    int b = a++;  // b에 5를 넣고, 그다음 a는 6
    int c = ++a;  // a를 7로 만들고, 그 값 7을 c에
    cout << a << ' ' << b << ' ' << c << '\n';
    return 0;
}

#include <iostream>

    int m = n-- * 10;  // 3 * 10을 계산하고, n은 2
    int k = 3;
    int r = --k * 10;  // k를 2로 만들고, 2 * 10
    cout << n << ' ' << m << '\n';

    return 0;
}

핵심 정리
  • 혼자 쓰면 i++와 ++i는 같다. 5장의 for문에서 보게 될 i++가 바로 이 용법입니다.
  • 식 안에서 값을 쓰면 후위는 바뀌기 전 값, 전위는 바뀐 뒤 값을 낸다.
  • 헷갈리는 식을 쓰는 대신 두 문장으로 나눈다. int b = a; a++;가 int b = a++;보다 읽기 쉽습니다.

7논리 연산자: && || !

참·거짓 여러 개를 조합하는 연산자입니다. '20대인가?'는 '20 이상' 그리고 '30 미만'이고, '할인 대상인가?'는 '20 미만' 또는 '65 이상'입니다.

#include <iostream>
using namespace std;

int main() {
    int age = 25;
    bool in_twenties = (age >= 20) && (age < 30);
    bool discount = (age < 20) || (age >= 65);
    cout << in_twenties << ' ' << discount << ' ' << !in_twenties << '\n';
    return 0;
}

단축 평가

&&와 ||는 왼쪽을 먼저 계산하고, 왼쪽만으로 결과가 정해지면 오른쪽은 아예 실행하지 않습니다. 이것을 단축 평가(short-circuit evaluation)라고 합니다.

  • A && B: A가 거짓이면 B가 무엇이든 결과는 거짓 → B를 건너뜁니다.
  • A || B: A가 참이면 B가 무엇이든 결과는 참 → B를 건너뜁니다.

이 성질은 '위험한 계산 앞에 안전 검사를 두는' 데 씁니다.

#include <iostream>
using namespace std;

int main() {
    int a = 10;
    int b = 0;
    bool ok = (b != 0) && (a / b > 1);  // 오른쪽은 실행되지 않는다
    cout << ok << '\n';
    return 0;
}
실행 결과
0

b가 0이라 b != 0이 거짓이므로 a / b는 실행되지 않고, 프로그램은 0으로 나누지 않고 무사히 끝납니다. 두 조건의 순서를 바꿔 (a / b > 1) && (b != 0)으로 쓰면 나눗셈이 먼저 실행되어 2절에서 본 것처럼 프로그램이 죽습니다. 논리 연산에서는 순서가 의미를 가집니다.

오른쪽이 정말 실행되지 않는지 눈으로 확인해 봅시다. 오른쪽에 ++count를 넣어서, 실행되면 count가 늘어나게 했습니다.

#include <iostream>
using namespace std;

int main() {
    int a = 10;
    int count = 0;
    bool r1 = (a < 5) && (++count > 0);  // 왼쪽 거짓 → 건너뜀
    cout << r1 << ' ' << count << '\n';
    bool r2 = (a > 5) || (++count > 0);  // 왼쪽 참 → 건너뜀
    cout << r2 << ' ' << count << '\n';
    bool r3 = (a > 5) && (++count > 0);  // 왼쪽 참 → 오른쪽 실행
    cout << r3 << ' ' << count << '\n';
    return 0;
}

1 0
1 1

세 번째에서만 count가 1이 됐습니다. 원리를 보여 주려고 이렇게 썼지만, 실전에서는 &&, ||의 오른쪽에 값을 바꾸는 코드를 넣지 마세요. 실행될지 말지가 왼쪽에 달려 있어서 읽는 사람이 헷갈립니다.

max와 min

두 값 중 큰 것과 작은 것을 고르는 max, min은 <cmath>가 아니라 <algorithm> 헤더에 있습니다. 다른 헤더를 통해 우연히 컴파일되는 환경도 있지만 보장되지 않으므로 항상 직접 포함하세요.

#include <algorithm>
#include <iostream>
using namespace std;

int main() {
    int a = 4;
    int b = 9;
    int c = 6;
    cout << max(a, b) << ' ' << min(a, b) << '\n';
    cout << max(a, max(b, c)) << '\n';  // 셋 중 최댓값
    cout << min(2.5, 1.5) << '\n';
    return 0;
}

10비트 연산 맛보기

컴퓨터는 모든 정수를 2진수(0과 1)로 저장합니다. 비트 연산자는 이 2진수의 각 자리, 즉 비트(bit)를 직접 다룹니다. 코딩테스트에서는 홀짝 판정, 2의 거듭제곱, 부분집합 표현(18장)에, 임베디드에서는 레지스터 조작에 매일 씁니다. 여기서는 맛보기만 하고, 깊은 내용은 27장(코딩테스트)과 29장(임베디드)에서 다룹니다.

2진수 읽기

10진수의 각 자리가 오른쪽부터 1, 10, 100, …을 나타내듯, 2진수의 각 자리는 오른쪽부터 1, 2, 4, 8, 16, …(20, 21, 22, …)을 나타냅니다. 12 = 8 + 4이므로 8비트로 쓰면 00001100입니다.

11오버플로 다시 보기: 곱하기 전에 바꿔라

2장에서 int는 약 ±21억(INT_MAX = 2147483647)까지만 담을 수 있고, 부호 있는 정수가 넘치면(signed overflow) 정의되지 않은 동작이라는 것을 봤습니다. 그리고 넘친 결과를 long long에 담아 봐야 이미 늦다는 것도 잠깐 봤습니다. 이 절에서는 그 이유를 연산자의 규칙으로 정리하고, 변수끼리 곱할 때 어디서 변환해야 하는지 확인합니다.

  2. int * int이므로 곱셈은 int로 계산됩니다. 1012은 int에 들어가지 않아 오버플로가 일어납니다(정의되지 않은 동작).
  3. 이미 망가진 값이 long long 변수 x에 담깁니다. 담는 상자가 크다고 망가진 값이 되돌아오지는 않습니다.

12형 변환과 연산: 언제 실수가 되는가

지금까지 본 현상을 하나의 규칙으로 정리합니다. 이항 연산자의 두 피연산자 타입이 다르면, C++은 계산하기 전에 둘을 같은 타입으로 맞춥니다. 이것을 일반 산술 변환(usual arithmetic conversions)이라고 합니다. 코딩테스트에 필요한 만큼 줄이면 다음과 같습니다.

핵심 정리
  1. 한쪽이 double이면 다른 쪽도 double로 바뀌고, 결과도 double입니다.
  2. 한쪽이 long long, 다른 쪽이 int면 long long으로 맞춥니다.
  3. bool, char, short는 계산에 들어가는 순간 먼저 int로 바뀝니다(정수 승격, integer promotion). 그래서 'a' + 1은 98이고, 2장에서 본 true + true가 2입니다.
  4. 변환은 연산자 하나마다 따로 일어납니다. 식 전체를 미리 보고 정하지 않습니다.

정확히는 unsigned가 섞일 때의 규칙이 더 있습니다. 6절의 −1 < 0u가 거짓이 된 것이 그 예이고, 29장에서 정리합니다.

    cout << (double)(a / b) << '\n';
    cout << static_cast<double>(a) / b << '\n';
    return 0;
}

연습 포인트: 정수 / 정수 = 몫(2절). 함수형 템플릿의 answer에 식 하나를 넣는 가장 기본 형태입니다.

힌트 1

2절 첫 예제에서 7 / 2가 얼마였는지 떠올리세요. 이 문제의 예제 2와 같은 숫자입니다.

힌트 2

템플릿의 int answer = 0;을 int answer = num1 / num2;로 바꾸면 됩니다. 두 매개변수가 모두 int라서 /가 곧 몫입니다.

풀이 코드와 해설
#include <string>
#include <vector>

    int answer = num1 / num2;  // 정수 / 정수 = 몫

[PCCE 기출문제] 2번 / 피타고라스의 정리 Lv.0빈칸채우기(PCCE)필수

연습 포인트: 제곱을 곱셈으로 쓰기(^는 XOR, pow는 double — 9·10절). 입력을 받는 PCCE 형식에 익숙해지기.

힌트 1

피타고라스의 정리 a² + b² = c²를 b²에 대해 정리해 보세요. 출력할 값은 b가 아니라 b²입니다. 그 식을 C++로 어떻게 쓸까요?

힌트 2

b² = c² − a²입니다. C++에서 제곱은 c * c로 씁니다. c ^ 2는 제곱이 아닙니다(10절). 주어진 코드에서 b_square를 계산하는 줄을 이 식으로 고치세요.

풀이 코드와 해설
입력
3
5
#include <iostream>

int main(void) {
    int a;
    int c;
    cin >> a >> c;

    int b_square = c * c - a * a;  // 고친 줄
    cout << b_square << endl;
    return 0;
}
실행 결과
16

사이트에 주어지는 코드는 a와 c를 입력받고, b_square를 계산하고, 출력하는 몇 줄짜리 main입니다. 입력 줄과 출력 줄은 그대로 두면 되므로, 고칠 줄은 b_square를 계산하는 줄입니다. 그 줄을 c * c - a * a로 바꿉니다. *가 -보다 먼저 묶이므로 괄호 없이도 (c × c) − (a × a)로 계산됩니다. 예제 1은 25 − 9 = 16, 예제 2(9, 10)는 100 − 81 = 19로 둘 다 통과합니다. c ≤ 100이라 c * c는 최대 10000이고 오버플로 걱정이 없습니다.

변수를 초기화하지 않은 int a;와 endl은 사이트의 원래 코드 모양입니다. 바로 다음 줄에서 cin으로 값을 넣으므로 문제가 없고, 한 줄만 고치는 문제라서 나머지는 손대지 않습니다.

흔한 오답은 세 가지입니다.

  • c ^ 2 - a ^ 2: ^는 XOR입니다. 게다가 -가 ^보다 먼저 묶여서 c ^ (2 - a) ^ 2로 계산되고, c = 5, a = 3이면 −8이 나옵니다. 숫자가 아니라 변수라서 10절의 '혹시 1 << 3?' 경고도 나오지 않습니다(괄호를 권하는 -Wparentheses 경고만 나옵니다).
  • pow(c, 2) - pow(a, 2): 이 범위에서는 값이 맞지만, <cmath>가 필요하고 double을 int로 바꾸는 과정이 끼어듭니다. 정수 제곱은 곱셈이 정석입니다(9절).
  • sqrt로 b를 구해서 출력: 문제는 b가 아니라 b²을 요구합니다. 출력할 값을 정확히 읽으세요.

피자 나눠 먹기 (1) Lv.0함수형필수

피자 한 판을 7조각으로 자를 때, n명이 모두 한 조각 이상 먹으려면 피자가 최소 몇 판 필요한지 구하는 문제입니다.

연습 포인트: 올림 나눗셈 (a + b - 1) / b(3절)와 그 원리.

힌트 1

n / 7이 정답인 경우와 아닌 경우를 예제로 비교해 보세요. n = 7이면? n = 15면?

힌트 2

15명이면 2판(14조각)으로는 1명이 모자라 3판이 필요합니다. 나머지가 조금이라도 있으면 한 판을 더하는 '올림'입니다. 3절의 공식에 b = 7을 넣으세요.

풀이 코드와 해설
#include <string>
#include <vector>

using namespace std;

int solution(int n) {
    // n명을 7조각짜리 피자로: n / 7을 올림
    int answer = (n + 6) / 7;
    return answer;
}

(n + 7 - 1) / 7을 미리 계산해 (n + 6) / 7로 썼습니다. 예제 n = 7 → 13 / 7 = 1, n = 1 → 7 / 7 = 1, n = 15 → 21 / 7 = 3으로 모두 통과합니다. n이 1 이상이라 양수 조건도 만족합니다. 같은 뜻을 다르게 쓸 수도 있습니다.

#include <string>
#include <vector>

using namespace std;

int solution(int n) {
    // 나머지가 있으면 (n % 7 != 0)이 true → 1이 더해진다
    int answer = n / 7 + (n % 7 != 0);
    return answer;
}

(n % 7 != 0)은 bool이고, 정수와 더하면 12절 규칙 3에 따라 true는 1, false는 0이 됩니다. '몫에, 나머지가 있으면 1판 추가'를 그대로 옮긴 식입니다. 두 풀이는 n = 1 ~ 100 전체에서 같은 답을 내는 것을 확인했습니다. 흔한 오답은 이렇습니다.

  • n / 7 + 1: n = 7처럼 나누어떨어질 때 2가 나와 틀립니다. 예제 1이 바로 이 경우를 잡아 줍니다.
  • ceil(n / 7): 9절의 함정입니다. n / 7이 정수 나눗셈이라 n = 15에서 이미 2가 되고, ceil(2)는 2입니다.

간단한 논리 연산 Lv.0함수형추가

bool 값 x1, x2, x3, x4가 주어질 때, 논리식 (x1 ∨ x2) ∧ (x3 ∨ x4)의 결과를 돌려주는 문제입니다.

연습 포인트: 수학 기호 ∨(OR), ∧(AND)를 C++의 ||, &&로 옮기기. 괄호의 역할(7절).

힌트 1

∨는 '또는', ∧는 '그리고'입니다. 7절의 어떤 연산자에 해당할까요?

힌트 2

식을 그대로 옮기되 괄호를 살립니다. 반환 타입이 bool이므로 그 식의 결과를 그대로 return하면 됩니다.

풀이 코드와 해설
#include <string>
#include <vector>

using namespace std;

bool solution(bool x1, bool x2, bool x3, bool x4) {
    bool answer = (x1 || x2) && (x3 || x4);
    return answer;
}

예제 (false, true, true, true) → true, (true, false, false, false) → false를 통과하고, 16가지 입력 조합 전부에서도 식과 같은 값을 내는 것을 확인했습니다. 이 문제의 함정은 괄호입니다. 괄호를 빼고 x1 || x2 && x3 || x4라고 쓰면 &&가 먼저 묶여 x1 || (x2 && x3) || x4가 됩니다. 예제 2에 넣어 보면 괄호가 있을 때는 (T ∨ F) ∧ (F ∨ F) = T ∧ F = F로 정답이지만, 괄호가 없으면 x1이 참이라 바로 T가 되어 틀립니다. 비트 연산자로 (x1 | x2) & (x3 | x4)라고 써도 bool에서는 값이 같지만, 단축 평가가 없고 의도가 흐려지므로 논리 연산은 논리 연산자로 씁니다.

양꼬치 Lv.0함수형추가

양꼬치 1인분은 12,000원, 음료수는 2,000원이고 10인분마다 음료수 하나가 무료일 때, 양꼬치 n인분과 음료수 k개의 총 금액을 구하는 문제입니다.

연습 포인트: 몫으로 '몇 번 묶이는가' 세기, 문장을 식으로 옮기기, 오버플로 범위 점검(11절).

힌트 1

무료 음료수는 몇 개일까요? 10인분마다 1개입니다. n = 64면 몇 개일까요?

힌트 2

무료 개수 = n / 10. 돈을 내는 음료수는 k - n / 10개입니다. 총액 = 양꼬치 값 + 돈 내는 음료수 값.

풀이 코드와 해설
#include <string>
#include <vector>

using namespace std;

int solution(int n, int k) {
    int service = n / 10;  // 10인분마다 음료수 1개 무료
    int answer = n * 12000 + (k - service) * 2000;
    return answer;
}

예제 1: 무료 1개, 10 × 12000 + (3 − 1) × 2000 = 124000. 예제 2: 무료 6개, 64 × 12000 + 0 × 2000 = 768000. 둘 다 통과합니다. 결과 예시에 쓰인 124,000의 쉼표는 보기 좋게 쓴 것일 뿐이고, 실제로는 정수 124000을 return합니다.

제한사항 n / 10 ≤ k는 '무료로 받은 음료수는 모두 마신다'는 뜻이라 k - service가 음수가 되지 않습니다. 금액의 최댓값은 1,400만 원 정도(n = 999, k = 999일 때 13,788,000)라 int로 충분합니다. 11절의 표처럼 제한사항으로 최댓값을 계산해 보는 습관을 이 문제에서 연습하세요.

아이스 아메리카노 Lv.0함수형추가

아메리카노 한 잔이 5,500원일 때, 가진 돈 money로 최대 몇 잔을 살 수 있는지와 남는 돈을 순서대로 담아 돌려주는 문제입니다.

연습 포인트: 몫과 나머지를 함께 쓰기. 값 두 개를 돌려주는 vector 반환을 처음 맛보기.

힌트 1

15,000원으로 5,500원짜리를 몇 잔 살 수 있고 얼마가 남나요? 각각 어떤 연산인가요?

힌트 2

잔 수 = money / 5500, 남는 돈 = money % 5500. 반환 타입이 vector<int>이므로 return {잔 수, 남는 돈}; 모양으로 돌려줍니다.

풀이 코드와 해설
#include <string>
#include <vector>

using namespace std;

vector<int> solution(int money) {
    int cups = money / 5500;    // 살 수 있는 잔 수
    int change = money % 5500;  // 남는 돈
    return {cups, change};      // 지금은 이 모양 그대로(6장)
}

15000 / 5500 = 2잔, 15000 % 5500 = 4000원이 남습니다(5,500 × 2 = 11,000). 예제 5500 → [1, 0], 15000 → [2, 4000]을 통과합니다.

반환 타입 vector<int>는 정수 여러 개를 순서대로 담는 상자입니다. 6장에서 제대로 배우고, 지금은 return {cups, change};가 '이 두 값을 이 순서로 담아 돌려준다'는 뜻이라는 것만 알아 두세요. 템플릿에 있는 vector<int> answer;와 return answer;를 이 한 줄로 바꾸면 됩니다. 순서를 바꿔 {change, cups}로 돌려주면 틀립니다. money는 최대 1,000,000이라 계산 범위도 안전합니다(181잔, 4,500원).

개미 군단 Lv.0함수형추가

공격력이 5, 3, 1인 개미를 조합해 사냥감의 체력 hp를 정확히 맞출 때, 필요한 개미의 최소 마릿수를 구하는 문제입니다.

연습 포인트: 몫과 나머지를 다음 단계로 넘기기(3절 시간 변환과 같은 구조). '큰 것부터 쓰기'가 왜 맞는지 따져 보기.

힌트 1

마릿수를 줄이려면 공격력이 큰 개미를 최대한 많이 쓰는 것이 유리해 보입니다. hp = 23이면 장군개미 몇 마리를 쓰고, 남는 체력은 얼마인가요?

힌트 2

장군개미 = hp / 5, 남은 체력 = hp % 5. 남은 체력(0 ~ 4)에서 병정개미 = 남은 체력 / 3, 일개미 = 남은 체력 % 3. 세 수를 더합니다. 3절의 '시간, 분, 초'와 같은 구조입니다.

풀이 코드와 해설
#include <string>
#include <vector>

using namespace std;

int solution(int hp) {
    int general = hp / 5;    // 장군개미(5)를 최대한
    int rest = hp % 5;       // 남은 체력: 0~4
    int soldier = rest / 3;  // 병정개미(3)
    int worker = rest % 3;   // 일개미(1)
    int answer = general + soldier + worker;
    return answer;
}

예제 세 개를 모두 통과하고, 제한사항이 허용하는 hp = 0에서도 0을 돌려줍니다. 큰 것부터 최대한 쓰는 방법을 그리디(greedy)라고 하고, 24장에서 본격적으로 다룹니다. 그리디는 항상 맞는 방법이 아니라서, 쓸 때마다 '왜 맞는지'를 따져야 합니다. 이 문제에서는 다음과 같이 확인할 수 있습니다.

  • 최소 구성에 일개미가 3마리 이상 있을 수 없습니다. 일개미 3마리를 병정개미 1마리로 바꾸면 마릿수가 줄기 때문입니다.
  • 병정개미가 2마리 이상이면 장군개미 1 + 일개미 1(합 6)로 바꿀 수 있고, 마릿수는 같습니다. 그러니 병정개미는 1마리 이하라고 봐도 됩니다.
  • 병정개미 1 + 일개미 2(합 5)는 장군개미 1마리로 바꾸면 마릿수가 줄어듭니다.
  • 따라서 병정개미와 일개미가 맡는 체력은 최대 3 + 1 = 4로 5 미만이고, 장군개미 수는 정확히 hp / 5가 됩니다. 남은 0 ~ 4를 3과 1로 나누는 방법도 위 조건에서는 rest / 3, rest % 3 하나뿐입니다.

모든 경우에 '큰 것부터'가 정답인 것은 아닙니다. 공격력이 1, 3, 4라면 6을 만들 때 큰 것부터는 4 + 1 + 1로 3마리지만, 3 + 3이면 2마리입니다. 그래서 이 풀이는 hp = 0부터 1000까지 모든 값에 대해, 가능한 모든 조합 중 최솟값을 구하는 별도 프로그램과 비교해서 같은 답이 나오는 것도 확인했습니다.
