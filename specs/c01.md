## Topics to teach (in this order; each normally becomes one or more numbered h3 sections)
1. 프로그램이 실행되기까지: 소스 코드(.cpp) → 전처리(#include 내용 붙여넣기, #define 치환) → 컴파일(기계어 오브젝트 .o) → 링크(라이브러리와 합쳐 실행 파일) → 실행. 그림 또는 ol.steps. STM32 빌드(.c → .o → .elf → .hex/.bin을 보드에 굽기)와 같은 과정이라는 .emb.
2. 가장 작은 C++ 프로그램을 한 줄씩 해부: #include <iostream>(입출력 기능 가져오기), using namespace std;(std::cout을 cout으로 줄여 쓰기, 장단점 — 코딩테스트에선 편의상 쓰고 큰 프로젝트·헤더에선 쓰지 않음), int main() { … return 0; }(프로그램 시작점, 0은 정상 종료 신호), 중괄호 블록, 세미콜론 = 문장의 끝, 대소문자 구분.
3. cout으로 출력: << 연산자, 문자열 리터럴 "...", 여러 개 이어 출력, 숫자 출력, 계산식 출력(cout << 1 + 2 vs cout << "1 + 2").
4. 줄바꿈: '\n' vs endl(endl = 줄바꿈 + 버퍼 비우기(flush); 반복 출력이 많으면 느려질 수 있음 → 이 노트는 '\n' 사용), 줄바꿈이 없으면 출력이 이어 붙는다.
5. 이스케이프 시퀀스: \n, \t, \\, \", \' — 특수문자 출력 문제(181948) 직접 연결.
6. 주석: //, /* */, 주석으로 코드 잠시 끄기, 좋은 주석은 '왜'를 쓴다.
7. 공백·들여쓰기·대소문자: 컴파일러는 대부분의 공백을 무시하지만 사람을 위해 들여쓴다. Cout, Main 같은 대소문자 실수.
8. 컴파일 에러 읽는 법: 세미콜론 누락, 따옴표 누락, cout 오타, #include 누락을 실제 g++ 메시지로(data-check="error" + run err 블록). 'main.cpp:5:5: error: …' 형식(파일:줄:칸) 읽기, 첫 번째 에러부터 고치기, 에러 한 개가 여러 에러를 부르는 현상.
9. 입력 맛보기: cin >> 변수 (string str; cin >> str; / int a; cin >> a;) — 입출력형 문제 템플릿을 이해할 정도만. 공백에서 끊긴다는 것만 언급하고 자세한 건 2장.
10. C 언어로는: #include <stdio.h>, printf("Hello\n"); (.two로 C++ vs C 나란히). printf 서식은 2장·29장에서.
11. 프로그래머스 입출력형 문제 처음 풀기: 템플릿 구조와 '코드 실행' → 결과 비교 → '제출 후 채점' 흐름을 181952로 따라가기.

## Confusions you MUST address explicitly (each in a .pen box or a quiz)
- '\n'을 빠뜨려 한 줄로 붙어 나옴
- "Hello"(문자열) vs 'Hello'(잘못된 다중 문자 상수, 경고)
- endl의 마지막 글자는 소문자 L
- << 와 >> 방향(cout <<, cin >>: 데이터가 흐르는 방향)
- #include 줄 끝에 세미콜론을 붙이는 실수
- 출력 형식은 공백 하나까지 정확히 일치해야 정답
- main 철자, 중괄호 짝
