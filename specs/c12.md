## Topics to teach (in this order; each normally becomes one or more numbered h3 sections)
1. 같은 답, 다른 속도: 1부터 n까지 합(루프 vs 공식), 소수 판정(n vs √n). 실행 시간 측정 코드(chrono)를 보여 주되 숫자는 환경마다 다르다고 명시(측정값을 고정 출력으로 비교하지 말 것 — data-check=compile).
2. 연산 횟수 세기 → 빅오(Big-O): 최고차항만, 상수 무시. O(1), O(log n), O(n), O(n log n), O(n²), O(n³), O(2ⁿ), O(n!) 표(n = 10, 1000, 10⁶일 때 연산 수).
3. 코드에서 복잡도 읽기: 단일/중첩 루프, 절반씩 줄어드는 루프(log), 루프 안의 STL 연산(vector.erase(begin) O(n), find O(n), set.insert O(log n), sort O(n log n), unordered_map 평균 O(1)), 재귀(피보나치 2ⁿ).
4. 제한사항 → 허용 복잡도 표: C++에서 1초에 대략 10⁸번의 단순 연산이 상한이라는 경험칙(환경·연산 종류마다 다름). n ≤ 10: O(n!), ≤ 20: O(2ⁿ), ≤ 500: O(n³), ≤ 5,000: O(n²), ≤ 10⁶: O(n log n), ≤ 10⁷–10⁸: O(n), 더 크면 O(log n)/수학. 프로그래머스 효율성 테스트.
5. 공간 복잡도: int 10⁷개 = 40 MB, long long 8바이트, 큰 배열은 전역/vector로(지역 배열은 스택 크기 제한 — 일반적으로 수 MB).
6. 흔한 시간 초과 원인: 큰 vector/string 값 전달, s = s + c, vector 앞 삽입/삭제 반복, 루프 안의 find/count, 중복 계산, endl 남발, 입출력형에서 cin/cout 속도(ios::sync_with_stdio(false); cin.tie(nullptr); — printf와 섞지 말 것).
7. 오버플로 점검: 제한사항으로 최대 결과 추정(10⁵ × 10⁵ = 10¹⁰ → long long), 중간 계산, 정답이 크면 나머지 요구(1234567, 1,000,000,007) → 매 단계 %(덧셈/곱셈 분배).
8. 런타임 에러/틀렸습니다 원인 체크리스트: 범위 밖 인덱스, 빈 컨테이너, 0으로 나누기, 깊은 재귀, 초기화 안 한 변수, 엣지 케이스(n = 1, 빈 문자열, 모두 같은 값, 최대값, 음수), 출력 형식.
9. 디버깅 기술: 손 추적 표, 중간값 cout(프로그래머스 '코드 실행'의 출력 칸 — 제출 전에 지우기), 작은 반례 만들기, 느린 정답과 비교(스트레스 테스트 개념), assert.
10. 풀이 전략: 읽고 30초 안에 할 일(입력 크기 → 가능한 복잡도 → 후보 알고리즘), 의사코드 먼저, '느린 정답 → 최적화', 막히면 다음 문제, 부분 점수.
11. 복잡도를 줄이는 수학 도구: 에라토스테네스의 체, 약수 √n, gcd O(log n), 등차수열 합 공식.

## Confusions you MUST address explicitly (each in a .pen box or a quiz)
- O(2n) = O(n)
- 빅오는 실제 시간이 아니다(상수 차이)
- log의 밑은 무시
- 효율성만 실패할 때의 의미
- 정답인데 시간 초과면 알고리즘을 바꿔야 함
