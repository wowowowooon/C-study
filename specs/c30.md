## Topics to teach (in this order; each normally becomes one or more numbered h3 sections)
1. MCU 메모리 맵(Cortex-M 표준 맵 기준: 코드/Flash 영역, SRAM 0x2000_0000, 주변장치 0x4000_0000 근처 — 칩마다 다르니 레퍼런스 매뉴얼 확인), 섹션(.text .rodata .data .bss heap stack)의 저장 위치와 실행 위치, 스타트업 코드(리셋 → .data 복사 → .bss 0 → SystemInit → main), 링커 스크립트와 .map 파일 개념.
2. volatile: 최적화가 메모리 읽기를 없애는 예(-O2 어셈블리 차이는 개념 설명), 레지스터, ISR 공유 변수, volatile이 해 주지 않는 것(원자성, 메모리 순서).
3. static의 3가지 의미(지역 static, 파일 범위 static, C++ 클래스 static 멤버), extern(선언 vs 정의), const(Flash 배치 가능).
4. 메모리 매핑 레지스터 접근: #define REG (*(volatile uint32_t *)0x40020014), CMSIS 스타일 구조체 매핑(typedef struct { volatile uint32_t MODER; … } GPIO_TypeDef; #define GPIOA ((GPIO_TypeDef *)주소)) — PC 실습에서는 실제 주소 대신 배열을 가짜 레지스터로 사용(실제 주소 접근은 PC에서 크래시).
5. 구조체 패딩과 정렬: 정렬 규칙, sizeof 예측 퀴즈(실행으로 검증), 멤버 순서 최적화, offsetof, __attribute__((packed))와 비정렬 접근 위험, 통신 패킷은 바이트 단위 직렬화.
6. union: 같은 메모리를 여러 타입으로(C에서는 타입 재해석 허용, C++에서는 memcpy 권장), 레지스터 비트필드 union 패턴.
7. 비트필드: 배치는 구현 정의 → 하드웨어 매핑엔 주의.
8. 함수 포인터: 문법 int (*fp)(int), typedef, 콜백, 함수 포인터 배열(명령 테이블, 상태 머신 테이블), 인터럽트 벡터 테이블 = 함수 포인터 배열.
9. ISR 규칙: 짧게, 플래그/버퍼만, 공유 변수는 volatile + 원자성(critical section), 재진입성, ISR 안에서 printf/malloc 금지.
10. 링 버퍼 완전 구현(UART 수신): head/tail, 가득 참 판정, 단일 생산자(ISR)–단일 소비자(main)에서 안전한 조건, 2의 거듭제곱 크기 + 마스크. PC 하네스로 테스트(run 검증).
11. 동적 할당을 피하는 이유(단편화, 실패 처리, 결정성, MISRA C), 고정 크기 메모리 풀 개념.
12. 다중 파일 구조: .h(인터페이스)/.c(구현), 헤더 가드, extern 최소화, static으로 캡슐화, Makefile 기초, 링크 에러(undefined reference) 읽기.
13. 기술면접 단골 질문 정리(volatile, static, const 위치, 포인터 vs 배열, 메모리 영역, 엔디안 판별, 비트 문제, ISR 규칙, 스택 오버플로 원인, malloc 문제점) — 각 질문에 모범 답안을 <details>로.
