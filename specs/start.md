## Topics to teach (in this order; each normally becomes one or more numbered h3 sections)
1. 이 노트의 목표: Programmers Lv.3를 C++로 혼자 푸는 실력 + 임베디드 C/C++ 기본기. 출발점은 '한 줄도 못 쓴다'. 전체 지도: Part 0(시작) → Part A 언어 기초(1–12장) → Part B 알고리즘(13–28장) → Part C 임베디드 C/C++(29–31장) → 부록(치트시트, 에러 사전, 전체 문제 목록).
2. 로드맵 표: 모든 챕터를 한 표로(번호, 제목, 핵심 내용 한 줄, 다 끝나면 풀 수 있는 수준 예: 'Lv.0 입문 문제', 'Lv.1', 'Lv.2', 'Lv.3 일부'). 각 행에 <a class="go" href="#cNN" data-go>로 이동 링크. OUTLINE.md의 제목을 그대로 사용.
3. 학습 기간 예시(약속이 아니라 예): 하루 1–2시간 기준 Part A 6–10주, Part B 12–16주, Part C 3–4주. 시험 기간엔 쉬어도 된다. 꾸준함 > 몰아치기.
4. 이 노트 읽는 법(범례): .box 핵심 정리, .why 왜 하나, .pen 빨간펜(실수 주의), .emb 임베디드 연결, .tip 팁, .q 확인 문제(먼저 풀고 답 보기), .prob 프로그래머스 문제 카드(힌트1 → 힌트2 → 풀이), 실행 결과 상자, 끝났는지 확인 체크리스트, 다음 챕터로 상자. 실제 예시 요소를 하나씩 보여 주며 설명(예: 작은 .pen, 작은 .q).
5. 왜 C++로 코딩테스트를 보고, 왜 C도 따로 배우나: 코딩테스트는 C++ STL 덕분에 빠르고 짧게 풀 수 있음. 임베디드 현업에서 펌웨어(MCU)는 C가 주력, 로봇·자율주행·ROS 2·리눅스 응용은 C++가 주력, PC 툴·HMI는 C#도 쓰임, Python은 분석·자동화 보조. 그래서 순서는 C++ 기초(공통 문법) → 알고리즘 → 임베디드 C 심화. C와 C++는 문법의 대부분을 공유하므로 1–9장에서 C와의 차이를 계속 표시함.
6. 프로그래머스 사용법(사용자가 보낸 링크: 코딩테스트 연습 목록, 레벨·언어 필터): 문제 화면 구성(문제 설명, 제한사항, 입출력 예, 입출력 예 설명), 언어 선택 C++, 초기 코드, '코드 실행'(공개된 예제만 실행, cout 출력 확인 가능), '제출 후 채점'(숨은 테스트 케이스, 정확성/효율성 점수), '테스트 케이스 추가하기', '초기화', '다른 사람의 풀이'(정답 후 열람 권장), '질문하기'. 레벨 Lv.0–Lv.5와 레벨은 사이트 사정으로 바뀔 수 있다는 점(이 노트의 레벨은 2026년 확인 기준). 추천 문제 묶음: 코딩 기초 트레이닝(181xxx), 코딩테스트 입문(120xxx), PCCE 기출(빈칸 채우기·한 줄 고치기), 연습문제/고득점 Kit/카카오 기출.
7. 두 가지 문제 형식: 함수형(solution 함수만 완성, return으로 정답 반환, main은 채점기가 가짐) vs 입출력형(main을 직접 쓰고 cin으로 읽고 cout으로 출력). 두 템플릿을 data-check="none" 코드로 보여 주고 차이를 표로. 함수 자체는 8장에서 배우지만 2장부터 템플릿을 '모양 그대로' 사용한다고 예고. 입출력형은 삼성·백준 등 다른 시험에서 흔함.
8. 문제 푸는 7단계 루틴: ① 문제를 끝까지 읽고 입력/출력/제한사항에 밑줄 ② 입출력 예를 손으로 따라가기 ③ 제한사항으로 방법 정하기(12장 이후) ④ 한국어 의사코드 ⑤ 코드 작성(직접 타이핑) ⑥ 예제 + 내가 만든 엣지 케이스로 '코드 실행' ⑦ 제출, 틀리면 디버깅. 풀고 나서 '다른 사람의 풀이' 2–3개 비교, 3일 뒤 빈 화면에서 다시 풀기. 막혔을 때 규칙: 15–30분 혼자 → 힌트 1 → 10분 → 힌트 2 → 풀이 읽고 이해 → 덮고 다시 쓰기.
9. AI와 공부하는 규칙(바이브코딩 탈출): 문제 풀 때는 AI 자동완성/코드 생성 끄기. Claude는 '선생님'으로만: (a) 개념 질문(예제와 함께 설명해 달라), (b) 내 코드 리뷰(정답 코드 말고 틀린 이유 힌트만), (c) 반례 요청, (d) 풀이 후 더 나은 방법 비교. 바로 쓸 수 있는 질문 템플릿 3개를 .box로 제공(문제 링크/내 코드/내가 생각한 방법/막힌 곳/원하는 도움 수준). 사용자는 이 노트로 공부하다가 Claude에게 돌아와 질문할 예정임.
10. 개발 환경: 처음 1–7장은 프로그래머스 에디터만으로 충분. 로컬 환경은 선택: VS Code + g++ (Windows는 MSYS2의 MinGW-w64 또는 WSL), 컴파일/실행 명령 예: g++ -std=c++17 -Wall -Wextra main.cpp -o main 후 ./main (1장에서 컴파일 과정을 설명). 이 노트의 모든 예제는 g++ (64비트 리눅스)로 실제 컴파일·실행해서 결과를 확인했다고 명시해도 됨(사실임: 자동 검증 도구로 확인).
11. 진도 관리: 위쪽 챕터 버튼, 각 챕터 끝 '이 챕터 끝냈어요' 체크(✓ 표시), 문제 카드의 '풀었어요' 체크, 부록 C 전체 문제 목록에서 진도 확인. 이 체크는 지금 쓰는 브라우저에만 저장됨(다른 기기와 동기화 안 됨).
12. 처음 질문했던 문제 이야기: 사용자가 처음 Claude에게 물어본 문제는 [PCCE 기출문제] 1번 / 문자 출력(340207)이고 1장에서 스스로 풀게 된다는 연결 문장(동기 부여, 짧게).
