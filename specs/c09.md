## Topics to teach (in this order; each normally becomes one or more numbered h3 sections)
1. 메모리 모델: 바이트마다 주소, 변수 = 주소 + 크기, &x로 주소 보기(cout << &x, printf("%p")), 주소는 실행마다 달라질 수 있음(ASLR). .emb: MCU에선 고정 주소(SRAM 0x2000_0000, 주변장치 0x4000_0000 근처 — Cortex-M 표준 메모리 맵).
2. 포인터 변수: int* p = &x; *p로 읽기/쓰기, .mem 그림으로 단계별. 선언의 * 와 식의 *(같은 기호, 다른 의미), & 도 주소 연산자 vs 참조 선언.
3. 포인터의 크기와 타입: sizeof(int*) = 8(64비트) vs 4(Cortex-M), 타입이 필요한 이유(몇 바이트를 읽을지, +1의 크기).
4. nullptr/NULL, 초기화 안 된 포인터(wild), 널 역참조 → Segmentation fault(실행 데모는 ub로, 결과 설명), 항상 초기화.
5. 포인터와 함수: void swap(int* a, int* b) — C에는 참조가 없어서 포인터로, scanf("%d", &a)에 &가 필요한 이유(2장 약속 회수), 포인터로 여러 값 반환.
6. 포인터 연산과 배열: 배열 이름 → 첫 원소 주소(decay), a[i] == *(a + i), p + 1은 sizeof(T) 바이트 이동(주소 출력으로 증명), 포인터로 배열 순회, 포인터 빼기, 배열 밖 포인터는 정의되지 않은 동작.
7. 배열을 함수에 넘기기: void f(int arr[], int n) == void f(int* arr, int n) → 함수 안 sizeof(arr)은 포인터 크기 → 길이를 따로 넘긴다(프로그래머스 C 템플릿의 numbers_len 이유).
8. const와 포인터: const int* p / int* const p / const int* const p, 오른쪽에서 왼쪽으로 읽는 법. .emb: const 데이터는 Flash(.rodata)에 둘 수 있음.
9. 동적 메모리: new/delete, new int[n]/delete[], C의 malloc/free(sizeof 곱하기, void* 캐스팅, NULL 확인), calloc/realloc 간단히, 메모리 누수/댕글링 포인터/이중 해제, vector가 이 일을 대신해 준다(RAII 예고).
10. 메모리 영역: .text, .rodata, .data, .bss, 힙, 스택 그림 + '이 변수는 어디에?' 퀴즈. .emb: 링커 스크립트와 .map 파일, STM32 RAM에서 스택과 힙이 마주 보고 자람.
11. 참조 다시 보기: 포인터와 비교 표(null 불가, 다시 가리키기 불가, 문법), 언제 무엇을. 지역 변수의 참조/포인터 반환 = dangling.
12. C 문자열과 포인터: char s[] = "hi"(배열, 수정 가능) vs const char* p = "hi"(리터럴, 수정 불가), '\0' 찾기로 길이 구하기(strlen 원리), 문자열 복사 직접 구현. 2장의 "3" + "10" 에러 이유 회수(포인터끼리 덧셈).
13. 프로그래머스를 C로 풀기: C 템플릿 모양(int* solution(int numbers[], size_t numbers_len) / char* solution(const char* my_string)), malloc으로 결과 만들기, 문자열은 길이 + 1('\0') 할당, 실제 템플릿은 사이트에서 확인.
14. 스마트 포인터 맛보기(unique_ptr, make_unique) — 현대 C++에선 new/delete를 직접 쓰는 일이 드물다. 임베디드에선 동적 할당 자체를 제한하는 경우가 많다(30장).

## Confusions you MUST address explicitly (each in a .pen box or a quiz)
- int* a, b; 에서 b는 포인터가 아님
- *p++ 의 의미
- & 와 * 의 위치별 의미
- cout << char* 는 문자열로 출력됨((void*) 캐스트)
- delete vs delete[]
- malloc 크기에 sizeof 빠뜨림
- 문자열 할당 +1 누락
- sizeof(배열) vs sizeof(포인터)
- free 후 사용
